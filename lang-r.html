📊 R: 모든 것이 벡터이고,
"모름"은 전염된다R: everything is a vector,
and "unknown" is contagious

R 은 통계와 데이터 분석을 위해 만들어진 언어라 일반 언어와 사고방식이 다릅니다. 스칼라가 없는 벡터 중심 세계, 반복문 대신 벡터화, 그리고 결측값 NA 의 전염이 핵심입니다. 문법 입문은 건너뛰고 이 문턱 개념과 데이터프레임 · 함수형 도구 · 통계 모델을 실제로 실행한 코드로 설명합니다.

R was built for statistics and data analysis, so it thinks differently from general-purpose languages. The core is a vector-centred world with no scalars, vectorisation instead of loops, and the contagion of the missing value NA. Skipping syntax basics, this page explains those threshold concepts plus data frames, functional tools and statistical models with code that was really run.

코드와 출력은 제작 환경(R 4.3.3, 기본 패키지)에서 실행한 결과입니다. 일부 출력(난수 · 수치 정밀도)은 R 버전에 따라 다를 수 있습니다. 시연은 벡터 연산의 모형이며 테스트가 실제 R 과 대조합니다.

Code and output come from running R 4.3.3 (base packages) in the authoring environment; some output (random numbers, numeric precision) may differ with the R version. The demo models vector operations and is checked against real R by a test.

핵심 개념 10가지Ten core concepts

  
R 은 일반 언어와 사고방식이 달라 벡터 · 결측 · 인덱싱에서 처음 걸려 넘어집니다. 문법 입문은 건너뛰고 그 문턱을 넘기 위한 개념을 모았습니다.

  
R thinks differently from general-purpose languages and people first stumble on vectors, missing values and indexing. Skipping syntax basics, these are the concepts to get over that threshold.

  
① 모든 것은 벡터: 길이 · 타입 강제 · 1부터 시작① Everything is a vector: length, coercion, 1-based indexing

    
R 에는 "스칼라"가 없습니다. 5는 길이 1 벡터이고, 벡터의 원소는 모두 같은 타입이라 섞으면 가장 일반적인 타입으로 자동 변환(타입 강제)됩니다(논리 < 정수 < 실수 < 문자). 인덱스는 1 부터 시작하고 x[0]은 오류가 아니라 빈 벡터입니다. 이 벡터 중심 사고가 아래 벡터화의 바탕입니다.

    
R has no "scalars". 5 is a length-1 vector, and a vector's elements are all of one type, so mixing coerces automatically to the most general type (logical < integer < double < character). Indexes start at 1 and x[0] is not an error but an empty vector. This vector-centred thinking underlies vectorisation below.


x <- 5
print(length(x))                  # 스칼라도 길이 1 벡터
v <- c(10, 20, 30)
print(v[1]); print(v[0])          # 1 부터 시작, 0 은 빈 벡터
print(c(1, "a", TRUE))            # 타입 강제: 모두 문자로
print(typeof(c(1L, 2.5)))         # 정수 + 실수 → 실수(double)
[1] 1
[1] 10

② 벡터화와 재활용 규칙② Vectorisation and the recycling rule

    
연산은 원소별로 한꺼번에 일어나므로 반복문이 필요 없습니다: h / 100, h > 70. 길이가 다른 두 벡터는 짧은 쪽을 처음부터 반복(재활용)해 맞추는데, 긴 쪽 길이가 짧은 쪽의 배수가 아니면 경고합니다. 논리 벡터로 원소를 고르고(x[x > 70]), TRUE가 1 로 계산되는 성질(sum(x > 70) = 개수)을 자주 씁니다. 위 시연에서 직접 값을 바꿔 보세요. 반복문이 필요하면 거의 항상 벡터화 · apply 계열로 바꿀 수 있습니다(속도도 훨씬 빠릅니다).

    
Operations happen element-wise all at once, so no loop is needed: h / 100, h > 70. Two vectors of different lengths are matched by repeating (recycling) the shorter from its start, and R warns if the longer length is not a multiple of the shorter. You pick elements with a logical vector (x[x > 70]) and lean on TRUE counting as 1 (sum(x > 70) = a count). Change the values yourself in the demo above. When you think you need a loop, vectorising or an apply-family call is almost always possible (and far faster).


h <- c(82, 64, 91, 58)
print(h / 100)                        # 스칼라가 재활용됨
print(h[h > 70])                      # 논리 벡터로 고르기
print(ifelse(h >= 70, "ok", "check")) # 원소별 if
print(sum(h > 70))                    # TRUE 는 1 로 → 개수
print(c(1, 2, 3, 4) + c(10, 20))      # 짧은 쪽 재활용
[1] 0.82 0.64 0.91 0.58
[1] 82 91
[1] "ok"    "check" "ok"    "check"
[1] 2
[1] 11 22 13 24

  

  
③ NA · NULL · NaN: "모름"과 "없음"은 다르다③ NA, NULL, NaN: "unknown" vs "nothing"

    
NA는 "값이 있는데 모른다"(결측), NULL은 "아무것도 없다"(길이 0), NaN은 "수가 아님"(0/0)입니다. NA 는 전염됩니다: sum·mean·비교에 NA 가 끼면 결과도 NA 이고, NA == NA조차 NA 이므로 확인은 is.na()로 합니다. na.rm = TRUE로 빼고 계산하되 몇 개가 빠졌는지는 따로 확인하세요(조용히 빠집니다).

    
NA means "a value exists but is unknown" (missing), NULL "nothing at all" (length 0), and NaN "not a number" (0/0). NA is contagious: if an NA enters sum, mean or a comparison the result is NA, even NA == NA is NA, so test with is.na(). na.rm = TRUE drops them for the calculation, but check how many were dropped separately (they vanish silently).


x <- c(82, NA, 91, 58)
print(mean(x))                    # NA 가 전염
print(mean(x, na.rm = TRUE))
print(NA == NA); print(is.na(x))
print(length(NULL)); print(c(1, NULL, 3))   # NULL 은 합쳐지면 사라짐
print(0 / 0); print(1 / 0); print(is.nan(0 / 0))

[1] 77
[1] NA
[1] FALSE  TRUE FALSE FALSE
[1] 0
[1] 1 3
[1] NaN

[1] TRUE

  

  
④ 인덱싱: [ ] · [[ ]] · $ 와 이름④ Indexing: [ ], [[ ]], $ and names

    
[ ]는 같은 종류의 컨테이너를 돌려주고(리스트에 [ ]를 쓰면 리스트), [[ ]]와 $는 안의 원소 하나를 꺼냅니다. 음수 인덱스는 "그것을 빼고", 논리 벡터는 "참인 것만", 이름은 이름으로 고릅니다. 이 구분을 모르면 "왜 리스트가 나오지"에서 막힙니다.

    
[ ] returns the same kind of container ([ ] on a list gives a list), while [[ ]] and $ extract one element inside. A negative index means "all but that", a logical vector "only the TRUE ones", and names select by name. Not knowing this distinction is where "why did I get a list?" starts.


x <- c(a = 82, b = 64, c = 91)
print(x["b"]); print(x[c(TRUE, FALSE, TRUE)]); print(x[-1])

l <- list(id = "T1", tags = c("x", "y"))

print(class(l[["id"]]))     # [[ ]] → 안의 값
print(l$tags[2])

⑤ 데이터프레임: 열은 벡터, 행은 관측⑤ Data frames: columns are vectors, rows are observations

    
data.frame은 길이가 같은 벡터들(열)을 묶은 표입니다. 행 선택은 df[조건, ](쉼표 뒤가 열), 정렬은 df[order(...), ], 그룹별 집계는 aggregate 입니다. 같은 일을 tidyverse(dplyr의 filter · group_by · summarise + 파이프 |>)로 더 읽기 쉽게 쓰는 것이 요즘의 표준입니다(아래 비교).

    
A data.frame is a table binding equal-length vectors (columns). Choose rows with df[condition, ] (after the comma are columns), sort with df[order(...), ] and aggregate by group with aggregate. Doing the same in the tidyverse (dplyr's filter, group_by, summarise with the pipe |>) more readably is today's standard (compared below).


df <- data.frame(id = c("T1", "T2", "B1", "B2"),
                 type = c("transformer", "transformer", "breaker", "breaker"),
                 health = c(82, 64, 91, 58))
print(df[df$health >= 70, ])                    # 행 고르기
print(df[order(-df$health), "id"])              # 건전도 내림차순의 id
print(aggregate(health ~ type, data = df, FUN = mean))   # 종류별 평균
df$risk <- df$health < 60                       # 새 열
print(df)

⑥ 함수형 도구: apply 계열 · Map · Filter · Reduce⑥ Functional tools: apply family, Map, Filter, Reduce

    
R 은 함수형 언어의 성격이 강해 함수도 값입니다. sapply/lapply/vapply는 "각 원소에 함수 적용", Filter · Map · Reduce는 걸러내기 · 짝지어 적용 · 누적입니다. 결과 타입이 안정적이어야 하는 코드에서는 sapply 대신 vapply(반환 타입을 선언)를 쓰세요(아래 함정). 함수의 마지막 식이 자동으로 반환값입니다.

    
R leans functional so functions are values. sapply/lapply/vapply "apply a function to each element"; Filter, Map and Reduce filter, apply pairwise and accumulate. In code needing stable result types use vapply (which declares the return type) instead of sapply (see the pitfall below). A function's last expression is its return value automatically.


sq <- function(x) x^2
print(sapply(1:5, sq))
print(vapply(list(1:3, 4:9), length, integer(1)))   # 반환 타입을 못 박음
print(Filter(function(x) x %% 2 == 0, 1:10))
print(Reduce(`+`, 1:5, accumulate = TRUE))           # 누적합
print(unlist(Map(function(a, b) a * b, 1:3, 4:6)))

⑦ 값 의미론: 복사 후 수정(copy-on-modify)⑦ Value semantics: copy-on-modify

    
R 은 대입이나 함수 인자 전달 뒤에 고치면 원본은 그대로이고 복사본이 고쳐집니다. Python 의 "이름표 + 가변 객체"와 정반대여서 함수 안에서 인자를 바꿔도 밖에 영향이 없습니다(그래서 고친 값을 반환해 받아야 합니다). 실제로는 고칠 때까지 복사를 미루므로 비용이 작습니다. 예외는 환경(environment)으로, 참조처럼 공유됩니다.

    
In R, modifying after assignment or after passing as an argument leaves the original untouched and changes a copy. It is the opposite of Python's "name labels + mutable objects", so changing an argument inside a function does not affect the outside (you must return the changed value and take it). In practice the copy is deferred until the modification, so the cost is small. The exception is an environment, which is shared like a reference.


a <- c(1, 2, 3)
b <- a
b[1] <- 99
print(a)                               # a 는 그대로

f <- function(v) { v[1] <- 0; v }
print(f(a)); print(a)                  # 밖의 a 는 안 바뀜

e <- new.env()
g <- function(env) env$x <- 1
g(e)
print(e$x)                             # 환경만은 참조처럼 공유
[1] 1 2 3
[1] 0 2 3
[1] 1 2 3
[1] 1

  

  
⑧ 지연 평가와 비표준 평가(NSE)⑧ Lazy evaluation and non-standard evaluation (NSE)

    
함수의 인자는 처음 쓰이는 순간에야 평가됩니다(약속 promise). 그래서 기본값이 다른 인자를 참조할 수 있고, 안 쓰는 인자는 아예 계산되지 않습니다. subset(df, health > 10) · dplyr::filter(df, health > 10)에서 health가 변수가 아니라 열 이름으로 해석되는 것도 같은 원리(식을 값이 아니라 코드로 받아 나중에 데이터 안에서 평가)이며 비표준 평가라 부릅니다. 편리하지만 함수 안에서 변수 이름으로 열을 고르려 할 때 헷갈립니다.

    
A function's arguments are evaluated only when first used (promises). So a default can refer to another argument, and an unused argument is never computed. That health in subset(df, health > 10) or dplyr::filter(df, health > 10) is read as a column name, not a variable, is the same principle (the expression is captured as code and evaluated later inside the data), called non-standard evaluation. Handy, but confusing when you try to pick a column by a variable's name inside a function.


f <- function(x, y = x * 2) { x <- 10; y }
print(f(1))                            # y 는 쓸 때 계산 → 이미 x 는 10 → 20

g <- function(a) { cat("before\n"); a; cat("after\n") }
g({ cat("evaluated\n"); 1 })           # 인자는 처음 쓰는 곳에서 평가됨

df <- data.frame(h = c(5, 50, 80))
print(subset(df, h > 10))              # h 는 변수가 아니라 열 이름으로 해석
[1] 20
before
evaluated
after
   h
2 50
3 80

  

  
⑨ 통계가 한 줄: 수식 · lm · 검정⑨ Statistics in one line: formulas, lm, tests

    
R 이 사랑받는 이유입니다. 수식(y ~ x = "y 를 x 로 설명")으로 모델을 쓰고 lm(선형 회귀) · glm · t.test · cor.test 같은 함수가 객체를 돌려주면 coef · summary · predict · residuals로 꺼내 씁니다. 통계 방법의 대부분이 패키지로 이미 있으므로 직접 구현하기 전에 CRAN 에서 찾으세요.

    
This is why R is loved. You write a model as a formula (y ~ x = "explain y by x"), functions like lm (linear regression), glm, t.test and cor.test return an object, and you extract with coef, summary, predict and residuals. Most statistical methods already exist as packages, so search CRAN before implementing your own.


d <- data.frame(age    = c(2, 5, 8, 12, 15, 20),
                health = c(95, 90, 82, 71, 64, 52))
fit <- lm(health ~ age, data = d)                 # 건전도를 연식으로 설명
print(round(coef(fit), 3))                        # 절편과 기울기
print(round(summary(fit)$r.squared, 3))           # 설명력
print(round(predict(fit, data.frame(age = 10)), 1))   # 10년 된 설비의 예측
print(round(t.test(c(5.1, 4.9, 5.4, 5.6, 5.0), mu = 5)$p.value, 3))

⑩ 재현성: 난수 시드 · 패키지 고정 · 보고서⑩ Reproducibility: seeds, pinned packages, reports

    
분석은 다시 돌렸을 때 같은 결과가 나와야 합니다. 난수는 set.seed()로 고정하고, 패키지 버전은 renv로 기록하며, 코드 · 결과 · 설명을 한 문서에 묶는 R Markdown / Quarto로 보고서를 만듭니다. 작업 공간(.RData)에 의존하지 말고 스크립트가 처음부터 끝까지 돌아가게 하세요. Git 으로 스크립트를 관리하면 변경 이력도 남습니다.

    
An analysis must give the same result when rerun. Fix random numbers with set.seed(), record package versions with renv, and make reports with R Markdown / Quarto, which bind code, results and prose in one document. Do not depend on the workspace (.RData); make the script run from start to finish. Managing scripts with Git also keeps the change history.


set.seed(42)
print(sample(1:10, 3))
print(round(runif(2), 4))

print(sample(1:10, 3))                 # 같은 시드 → 같은 결과
[1]  1  5 10
[1] 0.8304 0.6417
[1]  1  5 10

흔한 함정 6가지: 증상 → 원인 → 해결Six common pitfalls: symptom → cause → fix

  
⚠ 1:length(x) 가 빈 벡터에서 거꾸로 돈다⚠ 1:length(x) runs backwards on an empty vector

    
증상. x 가 비어 있는데 반복문이 두 번 실행됩니다 (1, 0).
Symptom. x is empty yet the loop runs twice (1, 0).

    
x <- c()
for (i in 1:length(x)) cat("i =", i, "\n")
i = 1 
i = 0 


    
원인. 1:0은 빈 구간이 아니라 1, 0 으로 내려가는 수열입니다.
Cause. 1:0 is not an empty range but a sequence counting down 1, 0.

    
해결. seq_along(x)(또는 seq_len(n))를 씁니다.
Fix. Use seq_along(x) (or seq_len(n)).

    
x <- c()
for (i in seq_along(x)) cat("i =", i, "\n")     # 빈 벡터면 한 번도 돌지 않음
cat("done\n")
done


  

  
⚠ if 의 조건이 NA⚠ An if condition that is NA

    
증상. if 가 "값이 필요한 곳에 결측값"이라는 오류를 냅니다.
Symptom. if errors with "missing value where TRUE/FALSE needed".

    
x <- c(5, NA)
r <- tryCatch(if (x[2] > 3) "big" else "small", error = function(e) conditionMessage(e))
print(r)
[1] "missing value where TRUE/FALSE needed"


    
원인. 비교가 NA 이면 조건이 참도 거짓도 아닙니다. 데이터에 NA 가 있으면 불쑥 나타납니다.
Cause. A comparison that is NA is neither true nor false. It appears suddenly once the data has an NA.

    
해결. NA 를 먼저 is.na()로 걸러내고, 한 값만 검사하는 if 에는 &&(단축 평가)를 씁니다.
Fix. Screen NAs with is.na() first, and use && (short-circuit) in an if testing a single value.

    
x <- c(5, NA)
print(if (!is.na(x[2]) && x[2] > 3) "big" else "small or unknown")
[1] "small or unknown"


  

  
⚠ sapply 의 반환 타입이 상황마다 다르다⚠ The return type of sapply changes with the situation

    
증상. 입력이 빈 벡터일 때 숫자 벡터가 아니라 리스트가 나옵니다.
Symptom. With an empty input you get a list instead of a numeric vector.

    
print(class(sapply(1:3, function(i) i * 2)))
print(class(sapply(integer(0), function(i) i * 2)))
[1] "numeric"
[1] "list"


    
원인. sapply는 결과를 "가능하면 단순화"하는데 빈 입력에서는 단순화할 근거가 없어 list()를 돌려줍니다.
Cause. sapply "simplifies if possible", and with empty input there is nothing to base it on so it returns list().

    
해결. 결과 타입이 중요하면 vapply(반환 형식을 선언)를 씁니다.
Fix. When the result type matters use vapply (which declares the return format).

    
print(class(vapply(integer(0), function(i) i * 2, numeric(1))))   # 반환 타입을 선언 → 항상 numeric
[1] "numeric"


  

  
⚠ factor 를 숫자로 바꾸면 코드 번호가 된다⚠ Converting a factor to numbers gives its codes

    
증상. "10", "20" 이던 값이 1, 2 로 바뀝니다.
Symptom. Values that were "10" and "20" become 1 and 2.

    
f <- factor(c("10", "20", "10"))
print(as.numeric(f))
[1] 1 2 1


    
원인. factor는 값을 범주 번호로 저장하고 라벨을 따로 둡니다. as.numeric은 번호를 돌려줍니다.
Cause. A factor stores category codes with separate labels, and as.numeric returns the codes.

    
해결. as.numeric(as.character(f)). 읽어 들일 때 stringsAsFactors = FALSE(R 4.0+ 의 기본값)를 확인하세요.
Fix. as.numeric(as.character(f)). When reading data, confirm stringsAsFactors = FALSE (the default since R 4.0).

    
f <- factor(c("10", "20", "10"))
print(as.numeric(as.character(f)))     # 라벨(문자)을 거쳐서
[1] 10 20 10


  

  
⚠ 부동소수점을 == 로 비교⚠ Comparing floating-point numbers with ==

    
증상. 0.1 + 0.2 == 0.3이 FALSE 입니다.
Symptom. 0.1 + 0.2 == 0.3 is FALSE.

    
print(0.1 + 0.2 == 0.3)
print(0.1 + 0.2 - 0.3)
[1] FALSE
[1] 5.551115e-17


    
원인. 이진 부동소수점이 0.1 을 정확히 담지 못합니다 (모든 언어 공통).
Cause. Binary floating point cannot hold 0.1 exactly (true in every language).

    
해결. isTRUE(all.equal(a, b))로 오차를 허용해 비교합니다.
Fix. Compare with tolerance via isTRUE(all.equal(a, b)).

    
print(isTRUE(all.equal(0.1 + 0.2, 0.3)))      # 허용 오차 안에서 같은가
[1] TRUE


  

  
⚠ data.frame 의 열 하나를 고르면 형태가 변한다⚠ Selecting one column changes the shape

    
증상. 열 하나를 골랐더니 데이터프레임이 아니라 벡터가 되어 다음 코드가 깨집니다.
Symptom. Selecting one column gives a vector, not a data frame, and the next code breaks.

    
df <- data.frame(a = 1:2, b = 3:4)
print(class(df[, "a"]))
print(class(df["a"]))
[1] "integer"
[1] "data.frame"


    
원인. df[, "a"]는 차원을 줄여(drop) 벡터를 돌려주지만 df["a"]는 데이터프레임을 유지합니다.
Cause. df[, "a"] drops dimensions and returns a vector, while df["a"] keeps a data frame.

    
해결. 형태를 유지하려면 drop = FALSE 나 df["a"](또는 tibble)를 씁니다.
Fix. To keep the shape use drop = FALSE or df["a"] (or a tibble).

    
df <- data.frame(a = 1:2, b = 3:4)
print(class(df[, "a", drop = FALSE]))
[1] "data.frame"

# Physical AI

웹페이지: [physical-ai.html](https://1004aiteam-power.github.io/ontology-space/physical-ai.html)

## 1. 개념

**Physical AI**는 센서로 현실 세계를 **인지**하고, 상황을 이해해 **판단**하며, 구동기로 **행동**하는 AI입니다.
물리 법칙이 지배하는 공간에서 실시간으로 동작해야 한다는 점이 핵심입니다.

| 구성요소 | 내용 |
|---|---|
| 인지 (Perception) | 카메라, LiDAR, 레이더, IMU, 촉각 센서 |
| 판단 (Reasoning) | 월드 모델(세상이 어떻게 변할지 예측), 정책(다음 행동 선택) |
| 행동 (Action) | 모터, 바퀴, 관절, 그리퍼 — 안전과 실시간성 필수 |
| 학습 (Learning) | 행동의 결과로 개선. 현실의 실패는 비싸서 대부분 시뮬레이션에서 먼저 학습 |

### 생성형 AI와의 차이

| 구분 | 생성형 AI | Physical AI |
|---|---|---|
| 출력 | 글, 그림, 코드 | 행동 (조향, 관절 토크, 그리퍼) |
| 환경 | 디지털 | 물리 세계 |
| 학습 데이터 | 인터넷 규모 텍스트·이미지 | 귀한 로봇 상호작용 데이터 → 시뮬레이션·합성 데이터 |
| 실패의 대가 | 틀린 답변 | 파손, 사고, 안전 |
| 시간 제약 | 수 초 | 밀리초 단위 실시간 |

## 2. 관련 기술

### 로봇 파운데이션 모델 (VLA: Vision-Language-Action)
영상과 자연어 지시를 받아 로봇 동작을 출력합니다.

GR00T N1 (NVIDIA, 2025), Gemini Robotics (Google DeepMind, 2025).

### 시뮬레이션과 디지털 트윈
- 시뮬레이터: NVIDIA Isaac Sim / Isaac Lab, MuJoCo, Gazebo, PyBullet
- 월드 모델: 영상으로 학습해 다음 장면을 생성 (예: NVIDIA Cosmos), 합성 데이터 생성
- **Sim-to-Real 격차**: 가상에서 완벽해도 현실의 마찰·잡음·조명 차이로 실패할 수 있음
- **도메인 랜덤화** (Tobin et al., 2017): 학습 환경을 계속 바꿔 현실을 "또 하나의 변형"으로 만들기

### MuJoCo
**MuJoCo**(Multi-Joint dynamics with Contact)는 관절로 이어진 몸체와 접촉(충돌·마찰)을 빠르고 정확하게 계산하는 물리 엔진입니다.
Emo Todorov가 개발(2012)했고, Google DeepMind가 2021년 인수해 2022년부터 오픈소스(Apache-2.0)로 공개하고 있습니다.

- 강화학습 벤치마크: Gymnasium의 Ant · Humanoid · HalfCheetah, DeepMind Control Suite
- **MJX**: JAX 구현, GPU·TPU에서 수천 개 환경 병렬 / **Menagerie**: 실제 로봇 모델 모음
- 로봇은 MJCF(XML)로 기술하고, 파이썬에서 `mujoco.mj_step()`으로 한 스텝씩 진행

```python
import mujoco                      # pip install mujoco
model = mujoco.MjModel.from_xml_path("pole.xml")
data = mujoco.MjData(model)
data.qpos[0] = 0.3                 # 0.3 rad 기울인 채 시작
for _ in range(2000):              # 4초
    data.ctrl[0] = -20 * data.qpos[0] - 3 * data.qvel[0]   # 간단한 제어 정책
    mujoco.mj_step(model, data)
print(data.qpos[0])                # 0.0000 (MuJoCo 3.17로 확인)
```

| 시뮬레이터 | 개발 | 강점 | 주 용도 |
|---|---|---|---|
| MuJoCo | Google DeepMind | 정확하고 빠른 접촉 물리, 가벼움, 파이썬 API | 강화학습 연구, 보행·조작 |
| Isaac Sim / Isaac Lab | NVIDIA | 사실적 렌더링, GPU 병렬, 센서 시뮬레이션 | 휴머노이드·산업 로봇, 합성 데이터 |
| Gazebo | Open Robotics | ROS 연동 | 로봇 소프트웨어 통합 시험 |
| PyBullet | Erwin Coumans | 설치 쉬움, 가벼움 | 교육, 간단한 연구 |

### 센서 융합
카메라(색·물체 종류), LiDAR(정밀 거리), 레이더(속도·악천후), IMU(빠른 자세 변화, 드리프트)를
칼만 필터, 초기/후기 융합, BEV 융합 등으로 합칩니다.

### 원본 Python 코드 대비 개선

| 항목 | 원본 (pygame + neat-python) | 웹 버전 |
|---|---|---|
| 벽 판정·센서 | 화면 픽셀 색을 1px씩 검사 | 벽 선분 교차 계산 + 공간 격자 |
| 충돌 | 회전하지 않은 사각형 | 회전한 차체 네 모서리 ↔ 중심선 거리 |
| 조작 | 좌/우 on-off, 속도 고정 | 조향만 연속값(−1~+1)으로 학습, 속도는 사용자가 슬라이더로 정한 값(1~8, 0.5 단위)으로 고정 |
| 적합도 | 생존 시간 + `x > 850` 보너스 | 중심선 전진 거리(트랙 길이로 정규화) + 완주 시간 보너스, 역주행·정체 탈락 |
| M-M 트랙 | 꼭짓점이 V자로 뾰족 | 봉우리를 아치로 + 평활화, 겹침·급커브 검사 후 재생성 |
| 변이 확률 | 노드 0.5, 연결 0.7 | 0.03 / 0.12 + 종 분화 임계값 자동 조절 |
| 일반화 | 없음 | 도메인 랜덤화, 센서 잡음, 처음 보는 트랙 평가 |

### 라운드 진행
라운드 1부터 150대가 동시에 달리고, 2바퀴를 완주한 차가 없으면 다음 라운드(다음 세대)로 넘어갑니다.
한 대라도 2바퀴를 완주하면 성공으로 종료합니다.

차량 속도별 첫 성공 라운드 (M-M 트랙, 회전율 0.12 rad/스텝, 각 3회):

| 속도 | 2 | 4 (기본) | 5 | 6 |
|---|---|---|---|---|
| 첫 성공 라운드 | 3~7 | 7~11 | 18~32 | 40라운드 안에 성공 못함 (5 초과 시 화면에 경고) |

### 개발 중 측정한 일반화 결과
차량 속도 4, 30라운드 학습 후 처음 보는 무작위 트랙 30개 중 완주 수 (각 2회, 진화는 무작위라 실행마다 다름):

| 학습 방법 | 완주 |
|---|---|
| 둥근 트랙 하나 | 1, 7 (가상 환경에 과적합) |
| 둥근 트랙 + 도메인 랜덤화 | 20, 25 |
| M-M 트랙 (어려움) | 27, 24 |

### 두 번째 예제: NEAT 스네이크 ([neat-snake.html](../neat-snake.html))
같은 `neat.js`로 뱀 150마리가 각자의 60×60 판에서 동시에 Snake를 배웁니다. 큰 화면에는 게임 중인 뱀 중 상위 3마리를 한 판에 겹쳐 그립니다(각자 자기 게임이라 서로 부딪히지 않음, 학습은 150마리 전체). 자율주행이 조향 연속값 하나를 배웠다면, 여기서는 세 행동 중 하나를 고릅니다.

| 파일 | 역할 |
|---|---|
| [`assets/physai/snake-sim.js`](../assets/physai/snake-sim.js) | 게임 규칙, 센서(입력 7개), 시드 난수, 세대 학습기 (화면 없이 동작) |
| [`assets/physai/snake-app.js`](../assets/physai/snake-app.js) | 화면: 큰 판(상위 3마리 겹쳐 보기 + 선두 강조), 옆 패널 신경망, 개체군 미니 판, 학습 곡선, 최고 기록 다시 보기 |

| 항목 | 설계 |
|---|---|
| 입력 7개 | 위험(앞·왼쪽·오른쪽) 3 + 먹이 방향(앞·뒤·왼쪽·오른쪽) 4, 모두 머리 방향 기준 0/1 |
| 출력 3개 | 좌회전 / 직진 / 우회전 중 최댓값 |
| 적합도 | 먹이 × 100 + 생존 걸음 × 0.1, 개체당 3판 평균 |
| 종료 | 벽·몸 충돌, 먹이 없이 240걸음(굶주림), 20000걸음 |
| 공정성 | 같은 세대는 같은 시드(먹이 순서), 세대마다 시드 변경 |

입력 설계 메모: 먹이 방향을 화면 기준(위·아래·좌·우) + 현재 방향 one-hot(총 11개)으로 주면 "방향 × 먹이 위치" 조합을 배워야 해서 30세대 동안 먹이 3개에 머무는 실행이 있었습니다. 머리 기준으로 바꾼 뒤에는 20×20 판에서 6회 모두 1~2세대 안에 한 판 먹이 16~34개였습니다. 판을 60×60으로 키운 뒤 60세대 학습 시 한 판 최고 먹이 149~157개(3회)였고, 한 세대에 걸리는 시간은 판이 큰 만큼 길어졌습니다.

> NEAT는 교육용 예시입니다. 오늘날 Physical AI는 대규모 시뮬레이션 강화학습, 모방학습, 파운데이션 모델로 학습합니다.
> "가상에서 시행착오로 배우고 현실로 옮긴다"는 흐름은 같습니다.

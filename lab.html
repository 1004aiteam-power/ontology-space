HANDS-ON

직접 질의하고, 그래프로 보기Query it, see it as a graph

전력망 데이터를 브라우저 안에서 Cypher(Neo4j의 질의 언어)로 다룹니다. 서버 없이, RDF(Turtle) 파일을 Neo4j에 불러온 것과 같은 속성 그래프로 바꿔 메모리에 올리고, 작은 Cypher 엔진이 질의를 실행합니다.

Query grid data in your browser with Cypher, Neo4j's query language. No server: the RDF (Turtle) files are turned into the same property graph you would get by loading them into Neo4j, and a small Cypher engine runs your queries in memory.

RDF를 Neo4j처럼 불러오기 — 클래스(rdf:type)는 라벨이 되고 상위 클래스도 라벨로 함께 붙습니다(예: :Breaker:ProtectedSwitch:Switch:ConductingEquipment). 값은 속성(cim:IdentifiedObject.name → name), 개체를 가리키는 속성은 관계(cim:Terminal.ConductingEquipment → :CONDUCTING_EQUIPMENT)가 되고, 원래 IRI는 uri 속성에 남습니다. Neo4j의 neosemantics(n10s) 플러그인으로 불러올 때와 같은 생각이며, 이름은 n10s의 매핑 기능(n10s.mapping.add)으로 짧게 바꾼 모양입니다. 이 실습 엔진은 읽기 질의(MATCH · OPTIONAL MATCH · WHERE · WITH · UNWIND · RETURN, 가변 길이 경로, 집계, EXISTS)를 지원합니다.

Loading RDF the Neo4j way — classes (rdf:type) become labels, with parent classes added as labels too (e.g. :Breaker:ProtectedSwitch:Switch:ConductingEquipment). Values become properties (cim:IdentifiedObject.name → name), links to other individuals become relationships (cim:Terminal.ConductingEquipment → :CONDUCTING_EQUIPMENT), and the original IRI stays in a uri property — the same idea as Neo4j's neosemantics (n10s) plugin, with names shortened the way n10s's mapping feature (n10s.mapping.add) does. The lab engine supports read queries: MATCH · OPTIONAL MATCH · WHERE · WITH · UNWIND · RETURN, variable-length paths, aggregation and EXISTS.

예제 질의를 고르거나 직접 고쳐서 실행하세요 (Ctrl/⌘ + Enter). 결과에서 노드를 누르면 아래 그래프에서 해당 노드로 이동합니다.

Pick a preset or edit and run (Ctrl/⌘ + Enter). Click a node in the results to jump to it in the graph.

💡 쉽게 말하면In plain words

데이터에게 질문을 던지는 곳입니다. 위의 예제 버튼을 누르면 질문이 채워지고, ▶ 실행을 누르면 답이 표로 나옵니다. (e:Breaker)처럼 괄호는 노드, -[:CONNECTIVITY_NODE]->처럼 화살표는 관계입니다. 그림을 그리듯 찾고 싶은 모양을 적으면, 그 모양과 맞는 곳을 모두 찾아 표로 보여 줍니다. 처음이라면 "라벨별 개수"나 "도전성 설비 전체"부터 눌러 보세요.

This is where you ask the data questions. Click a preset to fill in a question, then ▶ Run to get answers as a table. Parentheses like (e:Breaker) are nodes; arrows like -[:CONNECTIVITY_NODE]-> are relationships. You draw the shape you are looking for, and every place in the data that matches it comes back as a row. New here? Try "Count by label" or "All conducting equipment" first.

데이터 검증 (형상검증, Cypher)Data validation (shape checks in Cypher)

"선로는 단자 2개", "mRID는 UUID 형식" 같은 규칙을 위반을 찾는 Cypher 질의로 적어 두고, 고른 데이터에 모두 실행합니다. 결과가 0행이면 통과입니다. 위 데이터 목록에서 규칙 위반 예제를 고르면 규칙이 무엇을 잡는지 볼 수 있습니다.

Rules such as "a line has two terminals" or "an mRID is a UUID" are written as Cypher queries that find violations and run against the selected data. Zero rows means the rule passes. Pick the rule-breaking sample in the dataset list above to see what the rules catch.

💡 쉽게 말하면In plain words

데이터의 맞춤법 검사기입니다. 규칙마다 "규칙을 어긴 것을 모두 찾아 줘"라는 질문을 하나씩 만들어 두고 한꺼번에 돌립니다. 아무것도 안 나오면 통과, 나오면 그 목록이 고칠 곳입니다.

A spell-checker for data. Each rule is a question, "find everything that breaks this rule", and they all run together. Nothing found means pass; anything found is the list of things to fix.

Neo4j에서 검증하는 두 가지 방법 — ① 제약조건은 규칙을 어긴 데이터가 저장되지 못하게 막습니다(예: CREATE CONSTRAINT FOR (o:IdentifiedObject) REQUIRE o.mRID IS UNIQUE). Community 에디션은 고유(UNIQUE) 제약만, 존재·타입 제약은 Enterprise 에디션입니다. ② 관계 수·값 범위·형식처럼 제약으로 표현할 수 없는 규칙은 아래처럼 위반을 찾는 질의로 검사하고, 데이터를 넣은 뒤나 정기적으로 실행합니다.

Two ways to validate in Neo4j — ① constraints stop rule-breaking data from being written at all (e.g. CREATE CONSTRAINT FOR (o:IdentifiedObject) REQUIRE o.mRID IS UNIQUE); Community edition has unique constraints only, existence and type constraints need Enterprise. ② Rules constraints cannot express — relationship counts, value ranges, formats — are checked with violation-finding queries like the ones below, run after loading or on a schedule.

지식 그래프Knowledge graph

위에서 고른 데이터를 그래프로 그립니다. 노드는 개체, 화살표는 관계(예: :EQUIPMENT_CONTAINER)입니다. 단자(Terminal)를 끄면 설비와 노드를 점선으로 바로 잇습니다.

💡 쉽게 말하면In plain words

데이터를 마인드맵처럼 그린 그림입니다. 점 하나가 사물(변전소, 차단기, 노드 등), 화살표가 "~에 속한다", "~에 연결된다" 같은 관계입니다. 색은 종류이고, 점을 누르면 그 사물의 속성과 관계가 모두 나옵니다. 마우스 휠로 확대해 보세요.

The data drawn like a mind map: each dot is a thing (substation, breaker, node…), each arrow a relationship such as "belongs to" or "connects to". Colour shows the kind; click a dot to see all its properties and relationships. Scroll to zoom.

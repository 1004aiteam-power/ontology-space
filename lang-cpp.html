🧩 C++: 수명은 스코프가 정한다C++: scope decides lifetime

C++ 는 C 의 속도에 추상화를 더한 언어입니다. 그 비결은 객체의 수명을 스코프에 묶는 RAII이고, 값 · 이동 · 소유권을 다루는 방식이 다른 언어와 가장 크게 다릅니다. 문법 입문은 건너뛰고 생성자와 소멸자가 언제 불리는지, 이동과 복사가 어떻게 다른지, 스마트 포인터가 소유권을 어떻게 표현하는지를 실제 실행한 코드로 설명합니다.

C++ is C's speed plus abstraction. The secret is RAII, tying an object's lifetime to its scope, and the way it handles value, move and ownership differs most from other languages. Skipping syntax basics, this page explains with code that was really run when constructors and destructors are called, how move differs from copy, and how smart pointers express ownership.

코드와 출력은 제작 환경(g++ 13, C++20, Linux 64비트)에서 실행한 결과입니다. 시연은 같은 환경에서 실행한 기록의 재생입니다. 컴파일러 · 표준 라이브러리에 따라 일부 출력(예: 오류 문구)이 다를 수 있습니다.

Code and output come from running g++ 13 (C++20) on 64-bit Linux in the authoring environment; the demo replays a record from the same environment. Some output (for instance error wording) may differ with compilers and standard libraries.

    핵심 개념 9가지Nine core concepts
    
  
    C++ 는 거대하므로 중급의 문턱인 개념만 추렸습니다: 수명(RAII) → 값/이동 → 소유권(스마트 포인터) → 추상화(상속 · 템플릿) → 현대 기능.
    
  
    C++ is huge, so only the concepts at the intermediate threshold are picked: lifetime (RAII) → value/move → ownership (smart pointers) → abstraction (inheritance, templates) → modern features.
    
  
    ① RAII: 자원의 수명을 객체의 수명에 묶는다① RAII: tying a resource's lifetime to an object's
    
    
    Resource Acquisition Is Initialization. 자원(메모리 · 파일 · 잠금 · 소켓)을 생성자에서 얻고 소멸자에서 놓는 객체로 감싸면, 스코프를 벗어나는 모든 길(정상 종료 · return · 예외)에서 소멸자가 자동으로 불려 해제를 빠뜨릴 수 없습니다. C++ 의 모든 것이 이 위에 서 있고, C 의 goto cleanup이 필요 없어지는 이유입니다. 위 시연의 첫 시나리오를 보세요.
    
    
    Resource Acquisition Is Initialization. Wrap a resource (memory, file, lock, socket) in an object that acquires in its constructor and releases in its destructor, and every way out of the scope (normal end, return, exceptions) calls the destructor automatically, so releasing cannot be forgotten. All of C++ stands on this and it is why C's goto cleanup is unnecessary. See the first scenario in the demo.
    

    #include <iostream>
#include <mutex>

std::mutex m;

    ② 값 의미론: 복사 · 참조 · const② Value semantics: copy, reference, const
    
    
    C++ 의 변수는 값 자체입니다(Java · Python 처럼 객체에 대한 참조가 아님). 그래서 f(Big b)는 복사하고, f(Big& b)는 원본을 고치며, f(const Big& b)는 복사 없이 읽기만 합니다. 큰 객체를 읽을 때는 const T&가 기본이고, 작은 기본 타입은 값으로 받습니다. const는 "고치지 않는다"는 약속을 컴파일러가 검사하게 해 줍니다.
    
    
    A C++ variable is the value itself (not a reference to an object as in Java or Python). So f(Big b) copies, f(Big& b) changes the original and f(const Big& b) only reads, without copying. For reading big objects const T& is the default, and small basic types are taken by value. const makes the compiler check the "I will not modify" promise.
    

    #include <iostream>
#include <vector>

struct Heavy {
    static inline int copies = 0;
    std::vector<int> data = std::vector<int>(1000);
    Heavy() = default;
    Heavy(const Heavy& o) : data(o.data) { ++copies; }
};

size_t by_value(Heavy h)       { return h.data.size(); }   // 복사 발생
size_t by_ref(const Heavy& h)  { return h.data.size(); }   // 복사 없음

int main() {
    Heavy h;
    by_value(h);
    std::cout << "after by_value: " << Heavy::copies << "\n";
    by_ref(h);
    std::cout << "after by_ref:   " << Heavy::copies << "\n";
}
    after by_value: 1
after by_ref:   1
    
  
    
  
    ③ 이동 의미론과 "규칙 0/3/5"③ Move semantics and the "rule of 0/3/5"
    
    
    std::move는 "이 객체는 곧 버릴 테니 내용을 가져가도 좋다"는 표시(오른값 참조로의 형변환)이고, 실제로 훔치는 일은 이동 생성자/대입이 합니다. 큰 컨테이너를 반환하거나 vector가 커질 때 복사 대신 이동되어 빨라집니다. 규칙: 자원을 직접 관리하는 클래스는 소멸자 · 복사 · 이동을 함께 정의(규칙 5)해야 하고, 가능하면 멤버를 스마트 포인터 · 컨테이너로 두어 아무것도 정의하지 않는 것(규칙 0)이 최선입니다. 이동 뒤의 원본은 쓰지 마세요(시연의 두 번째 시나리오).
    
    
    std::move is a mark meaning "this object is about to be discarded, so you may take its contents" (a cast to an rvalue reference); the actual stealing is done by the move constructor/assignment. Returning big containers or growing a vector moves instead of copying, making it fast. Rule: a class that manages a resource itself must define destructor, copy and move together (rule of 5), and ideally holds smart pointers or containers so it defines none of them (rule of 0). Do not use a moved-from object (the demo's second scenario).
    

    #include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::string> names;
    std::string s(30, 'x');            // 짧은 문자열 최적화를 넘는 길이
    names.push_back(s);                 // 복사: s 는 그대로
    names.push_back(std::move(s));      // 이동: 내용을 넘기고 s 는 비게 됨
    std::cout << names.size() << " " << names[1].size() << " " << s.size() << "\n";
}

    ④ 스마트 포인터: 소유권을 타입으로④ Smart pointers: ownership in the type
    
    
    new/delete를 직접 쓰지 않습니다. unique_ptr는 "나만 소유"(복사 불가, 이동만 가능, 오버헤드 거의 0), shared_ptr는 "여럿이 공유"(참조 카운트, 마지막 소유자가 사라지면 삭제), weak_ptr는 "소유하지 않고 지켜보기"(순환 참조를 끊음)입니다. 기본값은 make_unique이고, 공유가 정말 필요할 때만 shared_ptr를 씁니다. 함수 시그니처가 곧 소유권 문서가 됩니다(unique_ptr를 값으로 받으면 "넘겨받는다").
    
    
    You do not use new/delete directly. unique_ptr means "only I own it" (not copyable, movable, almost zero overhead), shared_ptr "many share it" (reference count, deleted when the last owner goes), weak_ptr "watch without owning" (breaks cycles). The default is make_unique; use shared_ptr only when sharing is truly needed. Function signatures become ownership documentation (taking a unique_ptr by value means "I take it over").
    

    #include <iostream>
#include <memory>

int main() {
    auto a = std::make_shared<int>(42);
    std::weak_ptr<int> w = a;                    // 소유하지 않고 관찰
    {
        auto b = a;                              // 소유자 둘
        std::cout << a.use_count() << " ";
    }
    std::cout << a.use_count() << " ";
    a.reset();                                   // 마지막 소유자가 사라짐
    std::cout << w.expired() << "\n";
}

    ⑤ 클래스 · 상속 · 가상 함수⑤ Classes, inheritance and virtual functions
    
    
    가상 함수(virtual)를 부르면 포인터 · 참조의 실제 객체 타입에 맞는 함수가 실행됩니다(런타임 다형성; 객체 안의 숨은 vtable 포인터로 구현). 규칙: 상속할 클래스의 소멸자는 virtual로, 재정의에는 override를 붙여 오타를 컴파일 때 잡고, 다형성 객체는 값이 아니라 포인터 · 참조로 다룹니다(값으로 넘기면 파생 부분이 잘려 나가는 슬라이싱).
    
    
    Calling a virtual function (virtual) runs the one matching the actual object type behind a pointer or reference (run-time polymorphism, implemented with a hidden vtable pointer in the object). Rules: give a base class a virtual destructor, mark overrides with override so typos fail at compile time, and handle polymorphic objects by pointer or reference, not by value (passing by value causes slicing, cutting off the derived part).
    

    #include <iostream>
#include <memory>
#include <vector>

struct Shape {
    virtual ~Shape() = default;                 // 상속할 클래스는 virtual 소멸자
    virtual double area() const = 0;            // 순수 가상: 인터페이스
};
struct Rect : Shape {
    double w, h;
    Rect(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
};
struct Circle : Shape {
    double r;
    explicit Circle(double r) : r(r) {}
    double area() const override { return 3.0 * r * r; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> v;
    v.push_back(std::make_unique<Rect>(2, 3));
    v.push_back(std::make_unique<Circle>(2));
    for (const auto& s : v) std::cout << s->area() << " ";   // 실제 타입의 area()
    std::cout << "\n";
}

    ⑥ 템플릿과 STL: 컨테이너 · 알고리즘 · 반복자⑥ Templates and the STL: containers, algorithms, iterators
    
    
    템플릿은 타입을 매개변수로 받는 코드 틀이고 컴파일러가 쓰는 타입마다 코드를 만들어 냅니다(그래서 런타임 비용이 없음). STL 은 컨테이너(vector · map · unordered_map · set)와 알고리즘(sort · find_if · transform · accumulate)을 반복자로 이어 붙입니다. 기본 컨테이너는 vector(연속 메모리라 캐시에 유리)이고, 직접 쓴 루프보다 이름 있는 알고리즘이 의도를 드러냅니다. 람다(⑦)와 함께 씁니다.
    
    
    A template is a code pattern parameterised by types; the compiler generates code for each type used (hence no run-time cost). The STL joins containers (vector, map, unordered_map, set) and algorithms (sort, find_if, transform, accumulate) through iterators. The default container is vector (contiguous memory, cache-friendly), and a named algorithm shows intent better than a hand-written loop. It pairs with lambdas (⑦).
    

    #include <algorithm>
#include <iostream>
#include <map>
#include <numeric>
#include <string>
#include <vector>

template <typename T>
T largest(const std::vector<T>& v) { return *std::max_element(v.begin(), v.end()); }

int main() {
    std::vector<int> health = {82, 64, 91, 58, 77};
    std::sort(health.begin(), health.end(), std::greater<>());
    int sum = std::accumulate(health.begin(), health.end(), 0);
    std::cout << largest(health) << " " << sum / (int)health.size() << "\n";

    std::map<std::string, int> count;               // 정렬된 키 순서로 유지
    for (std::string t : {"breaker", "cable", "breaker", "relay", "breaker"}) ++count[t];
    for (const auto& [name, n] : count) std::cout << name << "=" << n << " ";
    std::cout << "\n";
}

    ⑦ 람다와 캡처⑦ Lambdas and captures
    
    
    람다 [캡처](인자){ 몸체 }는 이름 없는 함수 객체입니다. 캡처가 핵심: [x]는 값 복사, [&x]는 참조, [=]/[&]는 쓰는 것 전부. 참조 캡처한 람다를 변수의 수명보다 오래 쓰면 매달린 참조가 됩니다(스레드 · 콜백에 넘길 때 주의). 바로 쓰고 버리는 알고리즘 인자라면 [&]가 편하고, 저장해 두거나 다른 스레드로 보낼 때는 값 캡처가 안전합니다.
    
    
    A lambda [capture](args){ body } is an unnamed function object. The capture is the key: [x] copies, [&x] references, [=]/[&] take everything used. If a lambda that captured by reference outlives the variable it holds a dangling reference (watch out when passing to threads and callbacks). For an argument used and discarded at once [&] is convenient; for one that is stored or sent to another thread, capture by value.
    

    #include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> h = {82, 64, 91, 58, 77};
    int limit = 70;
    auto good = [limit](int x) { return x >= limit; };   // 값 캡처
    limit = 90;                                           // 람다는 복사본을 가짐
    std::cout << std::count_if(h.begin(), h.end(), good) << " ";

    int calls = 0;
    std::for_each(h.begin(), h.end(), [&calls](int) { ++calls; });   // 참조 캡처: 바깥 변수를 고침
    std::cout << calls << "\n";
}

    ⑧ 예외 안전성과 noexcept⑧ Exception safety and noexcept
    
    
    예외가 던져져도 프로그램이 일관된 상태를 유지하는 정도를 보장 수준으로 나눕니다: 기본(누수 없음, 유효한 상태) · 강한(실패하면 호출 전 상태 그대로) · nothrow(절대 던지지 않음). RAII 가 기본 보장을 거의 공짜로 줍니다. 이동 생성자는 noexcept여야 vector가 커질 때 이동을 쓰고(아니면 안전을 위해 복사), 소멸자는 던지지 않아야 합니다. 예외는 "드문 오류"에 쓰고 흔한 분기 처리에는 반환값을 씁니다.
    
    
    Exception safety levels describe how consistent the program stays when an exception is thrown: basic (no leaks, valid state), strong (on failure the state is as before the call) and nothrow (never throws). RAII gives the basic guarantee almost for free. A move constructor must be noexcept for vector to move rather than copy when it grows, and destructors must not throw. Use exceptions for "rare errors" and return values for common branches.
    

    #include <iostream>
#include <type_traits>
#include <vector>

struct A { A() = default; A(const A&) { std::cout << "copy "; } A(A&&) noexcept { std::cout << "move "; } };
struct B { B() = default; B(const B&) { std::cout << "copy "; } B(B&&) { std::cout << "move "; } };   // noexcept 없음

int main() {
    std::vector<A> a; a.reserve(1); a.emplace_back(); a.emplace_back();   // 커질 때 기존 원소를 옮김
    std::cout << "| ";
    std::vector<B> b; b.reserve(1); b.emplace_back(); b.emplace_back();
    std::cout << "\n";
    std::cout << std::is_nothrow_move_constructible_v<A> << std::is_nothrow_move_constructible_v<B> << "\n";
}

    흔한 함정 5가지: 증상 → 원인 → 해결Five common pitfalls: symptom → cause → fix
    
  
    ⚠ 값으로 넘겨서 슬라이싱⚠ Slicing by passing a polymorphic object by value
    
    
    증상. 가상 함수를 불렀는데 파생 클래스의 동작이 안 나옵니다.
    Symptom. You call a virtual function but the derived behaviour does not appear.
    
    
    #include <iostream>
#include <string>

struct Animal { virtual std::string sound() const { return "..."; } virtual ~Animal() = default; };
struct Dog : Animal { std::string sound() const override { return "woof"; } };

void by_value(Animal a)       { std::cout << a.sound() << " "; }
void by_ref(const Animal& a)  { std::cout << a.sound() << "\n"; }

int main() { Dog d; by_value(d); by_ref(d); }
    ... woof
    

    
    원인. 값으로 받으면 기반 클래스 부분만 복사되어 파생 부분이 잘려 나갑니다.
    Cause. Taking it by value copies only the base part, cutting off the derived part.
    
    
    해결. 다형성 객체는 const Animal& · 포인터로 받습니다.
    Fix. Take polymorphic objects as const Animal& or by pointer.
    
    
  
    
  
    ⚠ map[] 는 키를 만들어 버린다⚠ map[] inserts the key
    
    
    증상. 읽기만 했는데 맵의 크기가 늘어납니다.
    Symptom. You only read, but the map grew.
    
    
    #include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> m;
    if (m["T9"] == 0) std::cout << "size after [] : " << m.size() << "\n";

    Cause. operator[] inserts a new entry with a default value when the key is missing.
    
    
    해결. 읽기에는 find · contains(C++20) · at(없으면 예외)를 씁니다.
    Fix. Use find, contains (C++20) or at (throws if missing) for reading.

int main() {

    ⚠ 부호 있는 수와 없는 수의 비교⚠ Comparing signed with unsigned
    
    
    증상. -1 < 1u 가 거짓이 됩니다.
    Symptom. -1 < 1u comes out false.
    
    
    #include <iostream>

int main() {
    std::cout << std::boolalpha << (-1 < 1u) << " " << (-1 < 1) << "\n";   // -Wextra 가 -Wsign-compare 로 경고
}
    false true
    

    
    원인. 두 타입이 섞이면 부호 있는 쪽이 부호 없는 수로 변환되어 -1 이 매우 큰 수가 됩니다. v.size()(부호 없음)와 int를 비교할 때 자주 생깁니다.
    Cause. When mixed, the signed value is converted to unsigned, so -1 becomes a huge number. It often happens comparing v.size() (unsigned) with an int.
    
    
    해결. 같은 부호의 타입으로 맞추거나 std::cmp_less(C++20)를 씁니다. -Wall -Wextra를 켜 두면 경고합니다.
    Fix. Match the signedness or use std::cmp_less (C++20). -Wall -Wextra warns about it.
    
    
  
    
  
    ⚠ 반환한 지역 변수의 참조 · 람다의 댕글링 캡처⚠ Returning a reference to a local / dangling lambda capture
    
    
    증상. 가끔 정상이고 가끔 엉뚱한 값이 나오며 환경마다 다릅니다.
    Symptom. It is sometimes right, sometimes wrong, and varies by environment.
    
    
    const std::string& bad() {
    std::string s = "grid";
    return s;                      // 반환 뒤 s 는 소멸 → 매달린 참조
}

std::function<int()> make_counter() {
    int n = 0;
    return [&n] { return ++n; };   // n 은 함수가 끝나면 사라짐
}
    

    
    원인. 참조(&)는 원본의 수명을 늘려 주지 않습니다. 사라진 지역 변수를 가리키면 정의되지 않은 동작입니다.
    Cause. A reference (&) does not extend the original's lifetime. Pointing at a vanished local is undefined behaviour.
    
    
    해결. 값으로 반환하세요(이동 · 복사 생략이 비용을 없앱니다). 람다는 값 캡처 + mutable로 상태를 가지게 합니다. -Wall이 일부를 경고하고, ASan(-fsanitize=address)이 나머지를 실행 중에 잡습니다.
    Fix. Return by value (move and copy elision remove the cost). Give lambdas state with by-value capture plus mutable. -Wall warns about some and ASan (-fsanitize=address) catches the rest at run time.
    
    
  
    
  
    ⚠ 반복 중 vector 변경(반복자 무효화)⚠ Changing a vector while iterating (iterator invalidation)
    
    
    증상. push_back/erase 뒤에 기존 반복자 · 포인터를 썼더니 충돌하거나 쓰레기가 나옵니다.
    Symptom. After push_back/erase, using an old iterator or pointer crashes or gives garbage.
    
    
    std::vector<int> v = {1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it == 2) v.push_back(4);   // 재할당이 일어나면 it 이 무효 → 정의되지 않은 동작
    

    
    원인. vector가 커지면 메모리를 통째로 옮기므로 이전 원소를 가리키던 반복자 · 포인터 · 참조가 모두 무효가 됩니다.
    Cause. When a vector grows it moves its whole storage, invalidating every iterator, pointer and reference to old elements.
    
    
    해결. 순회 중에는 구조를 바꾸지 말고, 지울 때는 erase-remove_if(C++20 은 std::erase_if)를, 추가는 순회가 끝난 뒤에 합니다.
    Fix. Do not change the structure while traversing; to delete use erase-remove_if (C++20: std::erase_if) and add after the traversal ends.
    
    
    #include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};
    v.erase(std::remove_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; }), v.end());   // erase-remove
    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
}

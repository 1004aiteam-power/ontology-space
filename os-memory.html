🧠 프로그램이 보는 주소는
진짜 주소가 아니다The addresses a program sees
are not the real ones

두 프로그램이 똑같이 "주소 0x4010에 써라"라고 해도 서로의 데이터를 덮어쓰지 않습니다. 각 프로그램은 자기만의 가상 주소 공간을 갖고, CPU 안의 MMU가 메모리에 접근할 때마다 그 주소를 물리 주소로 바꾸기 때문입니다. 이 변환 덕분에 프로세스끼리 격리되고, 실제 메모리보다 큰 프로그램도 돌아갑니다. 주소 하나를 넣고 그 변환 과정을 따라갑니다.

When two programs both say "write to address 0x4010", they do not overwrite each other. Each has its own virtual address space, and the MMU inside the CPU turns that address into a physical address on every memory access. This translation isolates processes from one another and lets programs larger than physical memory run. Enter an address and follow the translation.

주소 공간 64 KB(16비트), 페이지 4 KB, 페이지 16개, 프레임 몇 개로 크게 줄인 학습용 모형입니다. 실제 x86-64는 48비트 이상 주소를 4단계 페이지 테이블로 변환합니다. 교체 알고리즘의 폴트 수(교과서 참조열에서 FIFO 15 · LRU 12 · OPT 9, Belady 이상 현상 9 → 10)는 tests/os.test.mjs로 확인합니다.

A teaching model scaled down to a 64 KB (16-bit) address space, 4 KB pages, 16 pages and a handful of frames. Real x86-64 translates 48-bit or wider addresses through a four-level page table. The fault counts of the replacement algorithms (FIFO 15 · LRU 12 · OPT 9 on the textbook string, Belady's anomaly 9 → 10) are checked in tests/os.test.mjs.

주소 하나를 따라가기Follow one address

이 프로세스의 주소 공간: 페이지 0~1 코드(읽기만), 2~3 데이터, 4~6 힙(아직 한 번도 안 씀), 15 스택. 7~14는 할당되지 않았습니다.

This process's address space: pages 0–1 code (read-only), 2–3 data, 4–6 heap (never touched yet), 15 stack. Pages 7–14 are unmapped.

해 볼 것: ① "코드 읽기"를 두 번 눌러 두 번째는 TLB만으로 끝나는 것. ② "힙에 처음 쓰기" 다음 "메모리가 꽉 참"으로 가장 오래 안 쓴 페이지가 밀려나는 것. ③ "배열을 차례로 32번 읽기"와 "여기저기 32번 읽기"의 TLB 적중률 차이(지역성). ④ 프레임 수를 3으로 줄이면 폴트가 얼마나 늘어나는지.

Try: ① press "Read code" twice; the second time the TLB alone answers. ② "First write to the heap", then "Memory is full": the least recently used page is pushed out. ③ Compare the TLB hit rate of "Read an array in order" and "Read here and there" (locality). ④ Drop the frames to 3 and see how many more faults occur.

누구를 내보낼까: 페이지 교체Whom to evict: page replacement

메모리가 꽉 찼을 때 새 페이지를 올리려면 누군가를 내보내야 합니다. 앞으로 다시 쓸 페이지를 내보내면 곧 또 폴트가 납니다. 아래 숫자는 프로그램이 차례로 접근하는 페이지 번호(참조열)입니다.

When memory is full, someone must go to make room for a new page. Evict a page that will be needed again and another fault follows soon. The numbers below are the pages a program touches in order (the reference string).

빨간 칸 = 페이지 폴트로 새로 올림(✕ 표시는 누군가를 내보낸 경우), 초록 칸 = 이미 있어서 적중. Clock에서 작은 숫자는 참조 비트입니다.

Red = page fault, newly loaded (✕ when something was evicted); green = already there, a hit. In Clock the small digit is the reference bit.

프레임을 늘리면With more frames

해 볼 것: "Belady의 이상 현상"에서 FIFO 선이 프레임 3 → 4일 때 오히려 올라가는 것(9 → 10). LRU · OPT는 이런 일이 생기지 않습니다. "프레임보다 큰 고리"에서는 LRU가 매번 곧 쓸 페이지를 내보내 모든 접근이 폴트가 됩니다.

알아 둘 원리Principles worth knowing

① 왜 가상 주소인가① Why virtual addresses

격리: 다른 프로세스의 메모리는 아예 주소로 가리킬 수 없습니다. 단순함: 모든 프로그램이 같은 주소에서 시작한다고 생각하고 만들 수 있습니다. 여유: 당장 안 쓰는 페이지는 디스크에 두어 실제 메모리보다 큰 프로그램도 돕니다. 공유: 같은 라이브러리 코드는 물리 메모리에 하나만 두고 여러 프로세스의 페이지 테이블이 함께 가리킵니다.

Isolation: another process's memory cannot even be named by an address. Simplicity: every program can be built as if it starts at the same address. Room: pages not in use stay on disk, so programs larger than RAM still run. Sharing: one copy of a library's code in physical memory, pointed to by many processes' page tables.

② 페이지 테이블과 TLB② Page tables and the TLB

페이지 테이블은 메모리에 있어서, 주소를 바꿀 때마다 읽으면 접근이 두 배 이상 느려집니다(x86-64는 4단계라 최대 네 번 더). 그래서 CPU는 최근 변환 몇십~몇천 개를 TLB라는 작은 캐시에 둡니다. 프로그램은 대개 가까운 주소를 연달아 쓰므로(지역성) TLB 적중률은 보통 99% 가까이 됩니다. 프로세스를 바꾸면 TLB를 비우거나 프로세스 번호(PCID · ASID)로 구분해야 해서 문맥 전환이 비싸집니다.

The page table lives in memory, so reading it on every translation would make each access twice as slow or worse (up to four extra reads with x86-64's four levels). The CPU therefore keeps tens to thousands of recent translations in a small cache, the TLB. Programs usually touch nearby addresses in a row (locality), so TLB hit rates are typically close to 99%. Switching processes means flushing the TLB or tagging entries (PCID · ASID), one reason context switches are costly.

③ 페이지 폴트는 오류가 아니다③ A page fault is not an error

페이지 폴트는 "아직 메모리에 없다"는 신호일 뿐이고, 커널이 조용히 채워 넣은 뒤 명령을 다시 실행합니다. malloc으로 큰 메모리를 받아도 실제로 처음 쓸 때 페이지 단위로 채워지는 것(요구 페이징), fork가 메모리를 복사하지 않고 공유하다 누군가 쓸 때 복사하는 것(쓰기 시 복사)도 폴트를 이용합니다. 진짜 오류는 할당 안 된 주소나 권한 위반이고, 이때 프로세스는 SIGSEGV를 받습니다.

A page fault only means "not in memory yet"; the kernel quietly fills it in and restarts the instruction. A large malloc is backed page by page on first touch (demand paging), and fork shares memory until someone writes and only then copies it (copy-on-write): both rely on faults. The real errors are unmapped addresses and permission violations, for which the process gets SIGSEGV.

④ LRU를 흉내 내는 Clock④ Clock, an approximation of LRU

진짜 LRU는 접근할 때마다 시각을 기록해야 해서 하드웨어로 하기엔 너무 비쌉니다. 대신 MMU는 페이지를 쓸 때 참조 비트 하나만 켭니다. Clock은 프레임을 시계처럼 돌며 비트가 1이면 0으로 끄고 넘어가고, 0인 페이지를 내보냅니다. "한 바퀴 도는 동안 한 번도 안 쓴 페이지"를 고르는 셈입니다. OPT는 미래를 알아야 해서 실제로는 쓸 수 없고, 다른 방식이 얼마나 잘하는지 재는 기준입니다.

True LRU needs a timestamp on every access, too costly for hardware. Instead the MMU only sets a single reference bit when a page is used. Clock sweeps the frames like a clock hand, clearing bits that are 1 and evicting the first page found at 0: "a page not used during one full sweep". OPT needs to know the future, so it cannot be used for real; it is the yardstick for the others.

⑤ 스래싱⑤ Thrashing

프로세스가 자주 쓰는 페이지들(작업 집합)이 메모리에 다 들어가지 않으면, 올리자마자 내보내고 또 폴트가 나는 일이 끝없이 반복됩니다. CPU는 놀고 디스크만 바쁩니다. "프레임보다 큰 고리"가 그 모습입니다. 리눅스는 메모리가 정말 모자라면 OOM 킬러로 프로세스 하나를 끝내 버립니다.

When the pages a process uses often (its working set) do not fit in memory, pages are evicted right after being loaded and fault again, over and over. The CPU sits idle while the disk is busy. "Loop larger than memory" shows exactly that. When memory truly runs out, Linux's OOM killer ends a process.

⑥ 이 모형이 생략한 것⑥ What this model leaves out

여러 단계 페이지 테이블, 큰 페이지(2 MB · 1 GB), 실행 금지(NX) 비트, 커널 영역, 여러 프로세스가 프레임을 나눠 쓰는 일, 페이지 캐시와 스왑 영역의 구분, 미리 읽기(prefetch)는 넣지 않았습니다. 주소 변환 실험의 교체는 LRU로 고정했습니다.

Not included: multi-level page tables, huge pages (2 MB · 1 GB), the no-execute (NX) bit, the kernel's half of the address space, several processes competing for frames, the split between the page cache and swap, and prefetching. Replacement in the translation lab is fixed to LRU.

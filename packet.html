📦 데이터가 패킷이 되기까지How data becomes a packet

브라우저가 "GET /index.html"이라는 글자를 보내면, 그 글자가 그대로 전선을 타지는 않습니다. TCP · IP · 이더넷이 차례로 자기 헤더를 앞에 붙여 점점 큰 상자에 담습니다. 글자를 직접 넣어 보며 그 상자의 속, 한 바이트까지 들여다봅니다.

When a browser sends the text "GET /index.html", that text does not travel the wire as it is. TCP, IP and Ethernet each prepend their own header, wrapping it in ever larger boxes. Type your own text and look inside the box, down to single bytes.

실제 네트워크 장비가 아니라 브라우저 안에서 같은 규칙으로 바이트를 계산합니다. 체크섬과 FCS는 실제 알고리즘(RFC 1071, CRC-32)이며, 값은 테스트(tests/net.test.mjs)로 확인합니다.

This is not a real network: the page computes the bytes by the same rules inside your browser. The checksum and FCS use the real algorithms (RFC 1071, CRC-32) and are checked by a test (tests/net.test.mjs).

알아 둘 원리Principles worth knowing

① 왜 계층으로 나눌까① Why layers

각 계층은 바로 아래 계층이 "어떻게든 전달해 준다"고 믿고 자기 일만 합니다. TCP는 와이파이인지 광케이블인지 모르고, 이더넷은 안에 든 것이 웹 요청인지 영상인지 모릅니다. 덕분에 한 계층을 바꿔도(와이파이 → 5G) 나머지는 그대로 둡니다. 소프트웨어의 인터페이스 분리와 같은 발상입니다.

Each layer trusts the one below to "deliver somehow" and does only its own job. TCP does not know whether the link is Wi-Fi or fibre; Ethernet does not know whether the payload is a web request or a video. So one layer can change (Wi-Fi → 5G) while the rest stay as they are — the same idea as separating interfaces in software.

② 캡슐화와 그 반대② Encapsulation and its reverse

보낼 때는 위에서 아래로 헤더를 붙이고(캡슐화), 받을 때는 아래에서 위로 헤더를 벗깁니다(역캡슐화). 각 계층은 자기 헤더만 읽고 안쪽은 열어 보지 않습니다. 라우터가 IP 헤더까지만 보고 TCP 포트는 신경 쓰지 않는 것이 그 예입니다. 위의 "받는 쪽에서 벗기기" 버튼으로 반대 방향을 따라가 보세요.

Sending adds headers from the top down (encapsulation); receiving strips them from the bottom up. Each layer reads only its own header and never opens what is inside. A router, for instance, looks only as far as the IP header and ignores the TCP port. Use the "Switch to receiving" button above to follow the reverse direction.

③ MTU와 MSS: 왜 쪼개나③ MTU and MSS: why split

이더넷 한 프레임이 나르는 IP 패킷은 보통 1500바이트까지(MTU)입니다. 거기서 IP·TCP 헤더 40바이트를 빼면 데이터는 한 조각에 1460바이트(MSS). 더 큰 데이터는 TCP가 미리 잘라 조각마다 순서 번호를 매깁니다. 위에서 MTU를 줄이면 조각이 늘어나고, 조각마다 seq가 앞 조각의 데이터 바이트 수만큼 커지는 것이 보입니다.

An Ethernet frame usually carries an IP packet of up to 1500 bytes (the MTU). Minus 40 bytes of IP and TCP headers, each piece holds 1460 bytes of data (the MSS). TCP cuts bigger data up front and numbers every piece. Lower the MTU above and you get more pieces, each with a seq larger by the bytes the previous one carried.

④ 체크섬과 FCS: 깨진 것 찾기④ Checksum and FCS: spotting damage

보내는 쪽이 계산한 값을 헤더에 적어 두면, 받는 쪽이 같은 계산을 다시 해 비교합니다. 다르면 중간에 비트가 바뀐 것이니 버립니다. 이더넷의 FCS(CRC-32)가 가장 강하고, IP 체크섬은 머리말만, TCP 체크섬은 머리말과 데이터(와 IP 주소)를 지킵니다. 버려진 조각은 TCP가 재전송으로 되살립니다.

The sender writes a computed value into the header and the receiver recomputes it to compare. A mismatch means a bit flipped on the way, so the piece is dropped. Ethernet's FCS (CRC-32) is the strongest; the IP checksum guards the header only, the TCP checksum the header, the data and the IP addresses. TCP revives dropped pieces by retransmission.

⑤ 주소가 세 겹인 이유⑤ Why three kinds of address

MAC은 같은 네트워크 안에서 다음 장비를 가리키고, 라우터를 지날 때마다 바뀝니다. IP는 출발지와 최종 목적지 컴퓨터를 가리켜 끝까지 유지됩니다. 포트는 그 컴퓨터 안의 어느 프로그램인지를 가리킵니다. "건물(IP) → 호수(포트)", 그리고 건물 앞까지 가는 길의 다음 갈림길(MAC)이라고 생각하면 쉽습니다.

MAC names the next device on the same network and changes at every router. IP names the source and final destination computers and stays the same end to end. The port names the program inside that computer. Think "building (IP) → room (port)", plus the next turn on the way to the building (MAC).

⑥ 이 모형이 생략한 것⑥ What this model leaves out

TCP·IP 옵션(MSS 합의, 윈도우 배율, 타임스탬프), IP 조각화(경로 중간에서 더 작은 MTU를 만났을 때), ARP(IP로 MAC을 알아내기), 프리앰블, VLAN 태그, IPv6, TLS 암호화는 넣지 않았습니다. 그래서 실제 패킷 캡처(Wireshark)와 헤더 크기가 조금 다를 수 있습니다.

Not included: TCP/IP options (MSS negotiation, window scaling, timestamps), IP fragmentation (when a smaller MTU is met mid-path), ARP (finding a MAC from an IP), the preamble, VLAN tags, IPv6 and TLS encryption. Header sizes can therefore differ slightly from a real capture (Wireshark).

전력 분야도 다르지 않습니다. VPP와 분산에너지의 통신 표준(IEEE 2030.5, OpenADR, OCPP, IEC 61850)은 모두 이 스택 위에서 도는 애플리케이션 계층 규약입니다. 목록은 통신 · 데이터 표준에 있습니다.

Power systems are no different. The communication standards of VPPs and distributed energy (IEEE 2030.5, OpenADR, OCPP, IEC 61850) are all application-layer protocols running on this stack. They are listed in Standards.

POWER GRID ONTOLOGY

전력망 온톨로지Power grid ontology

EMS, DMS, SCADA, GIS, AMI, 자산관리… 같은 변압기를 시스템마다 다르게 표현하는 문제를, 공통 의미 모델인 IEC CIM으로 풉니다.

EMS, DMS, SCADA, GIS, AMI, asset management… each system describes the same transformer differently. IEC CIM solves this with a shared semantic model.

💡 쉽게 말하면In plain words
  • IEC CIM = 전 세계 전력회사가 함께 쓰는 "전력 설비 공용 사전". 변압기·차단기·선로를 무엇이라 부르고 어떻게 연결하는지 정해 둠
  • IEC 61970 / 61968 / 62325 = 그 사전의 송전 편 / 배전 편 / 전력시장 편
  • CGMES = 유럽 송전회사들이 계통 모델을 주고받을 때 쓰는 택배 포장 규격. 사전(CIM)에서 필요한 부분만 골라 정해진 상자에 담음
  • IEC 61850 = 변전소 안 장치들끼리 대화하는 무전 규칙
  • IEC CIM = a shared dictionary of power equipment used worldwide: what to call transformers, breakers and lines, and how they connect
  • IEC 61970 / 61968 / 62325 = the transmission / distribution / market volumes of that dictionary
  • CGMES = the parcel-packing standard European grid operators use to exchange models: pick the needed parts of CIM and pack them into fixed boxes
  • IEC 61850 = the radio etiquette devices inside a substation use to talk to each other

Equipment and connectivity

Topology after switch states

SSH

해석 입력 조건 (부하, 발전, 탭)

Analysis inputs (loads, generation, taps)

SV

조류계산 결과 (전압, 위상, 조류)

Power flow results (voltage, angle, flow)

💡 쉽게 말하면In plain words

같은 지도 위에 겹쳐 놓는 투명 필름 네 장이라고 생각하면 됩니다. EQ는 도로망 지도(어떤 설비가 어떻게 이어졌나), TP는 지금 실제로 다닐 수 있는 길(열리고 닫힌 스위치 반영), SSH는 오늘 가정한 교통량(부하·발전량), SV는 내비게이션이 계산한 결과(각 지점의 전압·전력 흐름)입니다.

Think of four transparent sheets stacked on one map: EQ is the road network (what equipment connects to what), TP the roads actually open right now (switch states applied), SSH today's assumed traffic (loads and generation), and SV the navigation result (voltages and flows everywhere).

CIM 핵심 모델The CIM core model

모든 객체는 IdentifiedObject(mRID, name)에서 시작합니다.

Everything starts from IdentifiedObject (mRID, name).

IdentifiedObject
 └─ PowerSystemResource
     ├─ EquipmentContainer
     │   ├─ Substation          변전소
     │   ├─ VoltageLevel        전압계급
     │   ├─ Bay                 베이
     │   └─ Line                선로
     └─ Equipment
         └─ ConductingEquipment 도전성 설비 (Terminal 보유)
             ├─ ACLineSegment   교류 선로 구간
             ├─ PowerTransformer 변압기
             ├─ Switch ─ Breaker / Disconnector / LoadBreakSwitch
             ├─ BusbarSection   모선
             ├─ EnergyConsumer  부하
             └─ SynchronousMachine 동기발전기

Terminal · ConnectivityNode · TopologicalNode · BaseVoltage · Measurement

💡 쉽게 말하면In plain words
  • 분류 계층은 생물 분류(동물 ⊃ 포유류 ⊃ 고양이)와 같습니다. 차단기 ⊂ 개폐기 ⊂ 전기가 흐르는 설비 ⊂ 설비. 그래서 "설비를 모두 찾아"라고 하면 차단기도 함께 찾아집니다.
  • 포함 관계는 건물 구조와 같습니다. 변전소(건물) ⊃ 전압계급(층) ⊃ 베이(방) ⊃ 설비(가구)
  • mRID와 name: 모든 객체는 바뀌지 않는 번호(mRID)와 사람이 읽는 이름(name)을 함께 가집니다.
  • The class hierarchy works like biology (animal ⊃ mammal ⊃ cat): breaker ⊂ switch ⊂ conducting equipment ⊂ equipment, so "find all equipment" also finds breakers.
  • Containment works like a building: substation (building) ⊃ voltage level (floor) ⊃ bay (room) ⊃ equipment (furniture)
  • mRID and name: every object has an unchanging number (mRID) and a human-readable name.

연결 패턴: Terminal과 ConnectivityNodeConnectivity pattern: Terminal and ConnectivityNode

CIM은 설비끼리 직접 연결하지 않습니다. 각 설비의 Terminal(단자)이 ConnectivityNode(접속 노드)에 붙는 방식으로 연결합니다. 그래서 차단기 개폐에 따라 토폴로지를 다시 계산하거나, 그래프 탐색으로 정전 범위를 찾을 수 있습니다.

CIM never links equipment directly. Each piece of equipment has Terminals that attach to ConnectivityNodes. This makes it possible to re-run topology when switches change and to find outage areas by graph search.

💡 쉽게 말하면In plain words

플러그와 멀티탭을 떠올리세요. 각 설비에는 플러그(Terminal)가 달려 있고, 설비끼리 선을 직접 잇지 않고 모두 멀티탭(ConnectivityNode)에 꽂습니다. 그래서 어떤 스위치를 끄면 그 멀티탭 너머로 전기가 어디까지 안 가는지 하나씩 따라가 볼 수 있습니다.

Picture plugs and power strips. Every device has plugs (Terminals), and devices never wire straight to each other — they all plug into power strips (ConnectivityNodes). That is why, when a switch opens, you can trace step by step where power no longer reaches.

mRID: 설비의 주민등록번호mRID: the equipment's permanent ID

CIM의 모든 객체는 IdentifiedObject.mRID(Master Resource Identifier)를 가집니다. 시스템 간에 같은 설비를 가리키는 유일한 근거입니다.

Every CIM object carries IdentifiedObject.mRID (Master Resource Identifier), the only reliable way for systems to agree on "the same equipment".

CIM의 정의: mRID는 모델 관리 주체가 발급하며, 교환 범위 안에서 유일해야 합니다. 전역 유일성은 UUID로 쉽게 얻을 수 있으므로 UUID 사용을 강력히 권장합니다.
From the CIM: the mRID is issued by a model authority and is unique within an exchange context. Global uniqueness is easily achieved with a UUID, which is strongly recommended.
💡 쉽게 말하면In plain words

"M.Tr #1"이라는 이름의 변압기는 변전소마다 있고, 이름은 바뀔 수도 있습니다. mRID는 그 설비만의 주민등록번호입니다. 송전 운영 시스템, 설비관리 시스템, 지도 시스템이 같은 변압기를 이야기할 때 이 번호로 서로 확인합니다.

Almost every substation has a transformer called "M.Tr #1", and names can change. The mRID is that one device's national ID number; operations, asset and GIS systems use it to agree they mean the same transformer.

RDF 파일에서의 표기How it appears in RDF files

<!-- CGMES 2.4.15 : 파일 기준 상대 IRI (rdf:ID / rdf:resource="#_…") -->
<cim:Breaker rdf:ID="_6f1c2a9e-…">
  <cim:IdentifiedObject.name>154kV 선로 CB</cim:IdentifiedObject.name>
  <cim:Equipment.EquipmentContainer rdf:resource="#_0b7d…"/>
</cim:Breaker>

<!-- IEC 61970-552 Ed.2 / CGMES 3.0 : 위치와 무관한 urn:uuid -->
<cim:Breaker rdf:about="urn:uuid:6f1c2a9e-…"> … </cim:Breaker>
💡 쉽게 말하면In plain words

파일 안에 번호를 적는 두 가지 방식입니다. #_번호는 "이 파일 안의 ○번"이라는 뜻이고, urn:uuid:번호는 어디에 가져가도 통하는 번호라는 뜻입니다.

Two ways to write the number in a file: #_number means "number ○ within this file", while urn:uuid:number is a number that works anywhere.

발급 전략Issuing strategy

상황방법
새 설비를 모델에 처음 등록UUID v4 발급 후 저장. 이후 계속 같은 값 사용
기존 시스템(SCADA, GIS, 설비관리)의 데이터를 CIM으로 변환조직 네임스페이스 + 기존 설비코드로 UUID v5 → 변환을 다시 돌려도 같은 mRID
Terminal, TransformerEnd 같은 종속 객체부모 mRID + 번호로 v5 → 부모가 같으면 항상 같음
여러 시스템이 서로 다른 ID를 이미 쓰는 경우mRID를 기준으로 하는 매핑 테이블 (CIM Name / NameType으로 표현 가능)
SituationApproach
Registering new equipmentIssue a UUID v4, store it, and keep using it
Converting legacy data (SCADA, GIS, asset systems) to CIMUUID v5 from an organisation namespace + the legacy code → re-running the conversion gives the same mRIDs
Dependent objects (Terminal, TransformerEnd)v5 from the parent mRID + number → stable as long as the parent is
Several systems already use their own IDsA mapping table keyed by mRID (expressible with CIM Name / NameType)
💡 쉽게 말하면In plain words
  • 새 설비: 새 번호를 제비뽑기(v4)로 뽑아 장부에 적고 계속 씀
  • 옛 장부에서 옮겨 올 때: 옛 설비코드를 도장(v5)에 넣어 번호를 찍음 → 몇 번을 옮겨도 같은 번호
  • 부속품(단자 등): 본체 번호에서 이어 붙인 번호
  • 다른 시스템의 번호: 버리지 않고 "별명"으로 함께 적어 둠 (매핑 테이블)
  • New equipment: draw a new number (v4), record it, keep it
  • Moving from an old ledger: stamp the old code with v5 → the same number every time you migrate
  • Parts (terminals, etc.): numbers derived from the main device's number
  • Other systems' numbers: kept as "aliases" (a mapping table), not thrown away

변압기를 교체하면 mRID는?What happens to the mRID when a transformer is replaced?

CIM은 기능 위치(PowerSystemResource, 예: "A변전소 M.Tr #1 자리")와 물리 자산(Asset, IEC 61968, 예: 제조번호 XYZ-123인 변압기)을 구분합니다. 변압기를 교체하면 계통 모델의 PowerTransformer mRID는 그대로 두고, 새 Asset에 새 mRID를 발급해 연결합니다. 그래서 계통 해석 모델은 그대로 쓰면서 자산 이력도 추적할 수 있습니다.

CIM separates the functional position (PowerSystemResource, e.g. "M.Tr #1 bay at Substation A") from the physical asset (Asset, IEC 61968, e.g. serial no. XYZ-123). On replacement, the PowerTransformer mRID stays; the new Asset gets a new mRID and is linked to it. The network model is untouched while asset history is preserved.

pycim의 구현은 프로젝트 페이지에서 볼 수 있습니다.

See the pycim implementation on the Project page.

💡 쉽게 말하면In plain words

회사의 "팀장 자리"와 그 자리에 앉은 사람을 구분하는 것과 같습니다. 사람이 바뀌어도 팀장 자리는 그대로이고, 새로 온 사람은 새 사원번호를 받습니다. 변압기 자리(PowerTransformer)의 번호는 그대로 두고, 새로 들어온 기계(Asset)에만 새 번호를 줍니다. 그래서 계통 그림은 그대로 쓰면서 기계의 이력도 따로 관리할 수 있습니다.

It is like separating the team-lead position from the person in it: the position stays when people change, and each new person gets a new employee number. The transformer position (PowerTransformer) keeps its number; only the new machine (Asset) gets a new one — so the grid model stays intact while each machine keeps its own history.

💡 쉽게 말하면In plain words

차단기는 수도 밸브와 같습니다. 밸브를 잠그면 그 아래쪽 집들에 물이 끊기듯, 차단기를 열면 그 뒤쪽 설비에 전기가 끊깁니다. 이 그림은 멀티탭(노드)을 따라가며 전기가 어디까지 가는지 계산해 보여 주고, 숫자(pu)는 정상 전압을 1로 봤을 때의 비율입니다(0.99면 정상의 99%).

A breaker is like a water valve: close it and the houses downstream lose water; open a breaker and the equipment behind it loses power. The diagram follows the power strips (nodes) to show how far power reaches, and each number (pu) is voltage relative to normal (0.99 = 99% of normal).

SPARQL로 인접 설비 찾기Finding adjacent equipment with SPARQL

PREFIX cim: <http://iec.ch/TC57/CIM100#>
SELECT DISTINCT ?a ?b WHERE {
  ?t1 cim:Terminal.ConductingEquipment ?e1 ; cim:Terminal.ConnectivityNode ?cn .
  ?t2 cim:Terminal.ConductingEquipment ?e2 ; cim:Terminal.ConnectivityNode ?cn .
  FILTER(?e1 != ?e2)
  ?e1 cim:IdentifiedObject.name ?a .
  ?e2 cim:IdentifiedObject.name ?b .
}
💡 쉽게 말하면In plain words

"같은 멀티탭(ConnectivityNode)에 꽂혀 있는 설비 두 개를 모두 짝지어 보여 줘"라는 질문입니다. 이것만으로 어떤 설비가 어떤 설비와 바로 이웃해 있는지 전체 연결 지도를 얻을 수 있습니다.

The question is "pair up every two devices plugged into the same power strip (ConnectivityNode)". That alone yields the full map of which equipment sits right next to which.

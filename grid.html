POWER GRID ONTOLOGY

전력망 온톨로지Power grid ontology

EMS, DMS, SCADA, GIS, AMI, 자산관리… 같은 변압기를 시스템마다 다르게 표현하는 문제를, 공통 의미 모델인 IEC CIM으로 풉니다.

EMS, DMS, SCADA, GIS, AMI, asset management… each system describes the same transformer differently. IEC CIM solves this with a shared semantic model.

연결 패턴: Terminal과 ConnectivityNodeConnectivity pattern: Terminal and ConnectivityNode

CIM은 설비끼리 직접 연결하지 않습니다. 각 설비의 Terminal(단자)이 ConnectivityNode(접속 노드)에 붙는 방식으로 연결합니다. 그래서 차단기 개폐에 따라 토폴로지를 다시 계산하거나, 그래프 탐색으로 정전 범위를 찾을 수 있습니다.

CIM never links equipment directly. Each piece of equipment has Terminals that attach to ConnectivityNodes. This makes it possible to re-run topology when switches change and to find outage areas by graph search.

mRID: 설비의 주민등록번호mRID: the equipment's permanent ID

CIM의 모든 객체는 IdentifiedObject.mRID(Master Resource Identifier)를 가집니다. 시스템 간에 같은 설비를 가리키는 유일한 근거입니다.

Every CIM object carries IdentifiedObject.mRID (Master Resource Identifier), the only reliable way for systems to agree on "the same equipment".

CIM의 정의: mRID는 모델 관리 주체가 발급하며, 교환 범위 안에서 유일해야 합니다. 전역 유일성은 UUID로 쉽게 얻을 수 있으므로 UUID 사용을 강력히 권장합니다.
From the CIM: the mRID is issued by a model authority and is unique within an exchange context. Global uniqueness is easily achieved with a UUID, which is strongly recommended.

발급 전략Issuing strategy

상황방법
새 설비를 모델에 처음 등록UUID v4 발급 후 저장. 이후 계속 같은 값 사용
기존 시스템(SCADA, GIS, 설비관리)의 데이터를 CIM으로 변환조직 네임스페이스 + 기존 설비코드로 UUID v5 → 변환을 다시 돌려도 같은 mRID
Terminal, TransformerEnd 같은 종속 객체부모 mRID + 번호로 v5 → 부모가 같으면 항상 같음
여러 시스템이 서로 다른 ID를 이미 쓰는 경우mRID를 기준으로 하는 매핑 테이블 (CIM Name / NameType으로 표현 가능)
SituationApproach
Registering new equipmentIssue a UUID v4, store it, and keep using it
Converting legacy data (SCADA, GIS, asset systems) to CIMUUID v5 from an organisation namespace + the legacy code → re-running the conversion gives the same mRIDs
Dependent objects (Terminal, TransformerEnd)v5 from the parent mRID + number → stable as long as the parent is
Several systems already use their own IDsA mapping table keyed by mRID (expressible with CIM Name / NameType)

변압기를 교체하면 mRID는?What happens to the mRID when a transformer is replaced?

CIM은 기능 위치(PowerSystemResource, 예: "A변전소 M.Tr #1 자리")와 물리 자산(Asset, IEC 61968, 예: 제조번호 XYZ-123인 변압기)을 구분합니다. 변압기를 교체하면 계통 모델의 PowerTransformer mRID는 그대로 두고, 새 Asset에 새 mRID를 발급해 연결합니다. 그래서 계통 해석 모델은 그대로 쓰면서 자산 이력도 추적할 수 있습니다.

CIM separates the functional position (PowerSystemResource, e.g. "M.Tr #1 bay at Substation A") from the physical asset (Asset, IEC 61968, e.g. serial no. XYZ-123). On replacement, the PowerTransformer mRID stays; the new Asset gets a new mRID and is linked to it. The network model is untouched while asset history is preserved.

SPARQL로 인접 설비 찾기Finding adjacent equipment with SPARQL

PREFIX cim: <http://iec.ch/TC57/CIM100#>
SELECT DISTINCT ?a ?b WHERE {
  ?t1 cim:Terminal.ConductingEquipment ?e1 ; cim:Terminal.ConnectivityNode ?cn .
  ?t2 cim:Terminal.ConductingEquipment ?e2 ; cim:Terminal.ConnectivityNode ?cn .
  FILTER(?e1 != ?e2)
  ?e1 cim:IdentifiedObject.name ?a .
  ?e2 cim:IdentifiedObject.name ?b .
}

🐍 Python: 이름은 라벨이고
값은 객체다Python: names are labels,
values are objects

Python 은 쉬워 보이지만 객체 모델을 모르면 이상한 버그를 만납니다. 문법 입문은 건너뛰고, 변수와 객체의 관계 · 이터레이터와 제너레이터 · 데코레이터 · 동시성처럼 중급으로 넘어가는 개념을 실제 실행한 코드로 설명합니다. 맨 위 시연은 변수가 같은 객체를 가리키는 모습을 한 줄씩 보여 줍니다.

Python looks easy, but without its object model you meet strange bugs. Skipping syntax basics, this page explains the concepts that carry you to the intermediate level — how variables relate to objects, iterators and generators, decorators, concurrency — with code that was really run. The demo shows variables pointing at the same object, line by line.

코드와 출력은 제작 환경에서 Python 3.13 으로 실행한 결과입니다. 버전이 다르면 일부 출력(오류 문구 · 크기)이 다를 수 있습니다. 시연은 개념 설명용 모형입니다.

Code and output come from running Python 3.13 in the authoring environment; with other versions some output (error wording, sizes) may differ. The demo is a conceptual model.

    ① 변수는 이름표, 값은 객체① Names are labels, values are objects
    
    
    파이썬의 b = a는 값을 복사하지 않고 같은 객체에 이름을 하나 더 붙입니다. 객체가 가변(mutable)이면 한쪽에서 고쳐도 다른 이름으로 보입니다. is는 "같은 객체인가", ==는 "값이 같은가"입니다. 위 시연에서 직접 확인하세요.
    
    
    In Python b = a does not copy the value; it attaches one more name to the same object. If the object is mutable, a change through one name shows through the other. is asks "same object?", == asks "equal value?". Try it in the demo above.
    

    a = [1, 2]
b = a              # 같은 객체에 이름이 하나 더
b.append(3)
print(a, a is b)   # a 도 바뀌었다

c = list(a)        # 복사본: 새 객체
print(c is a, c == a)

    ② 가변과 불변, 그리고 += 의 두 얼굴② Mutable vs immutable, and the two faces of +=
    
    
    int · str · tuple은 불변이라 "바꾸는" 연산이 항상 새 객체를 만듭니다. 리스트는 가변이라 +=는 제자리에서 수정하고, +는 새 리스트를 만듭니다. 별명(alias)이 있을 때 이 차이가 결과를 가릅니다.
    
    
    int, str and tuple are immutable, so "changing" always creates a new object. A list is mutable: += modifies in place while + makes a new list. When aliases exist, this difference decides the outcome.
    

    s = "abc"
t = s
s += "d"          # 문자열은 불변 → 새 객체
print(s, t)

xs = [1, 2]
ys = xs
xs += [3]         # 리스트 += 는 제자리 수정 → ys 도 보임
print(xs, ys)
xs = xs + [4]     # + 는 새 리스트 → ys 는 그대로
print(xs, ys)

    for는 이터러블에서 이터레이터를 얻어 next()를 반복 호출합니다. yield가 든 함수는 제너레이터가 되어 값을 필요할 때 하나씩 만들고, 상태를 기억한 채 멈췄다 이어집니다. 큰 데이터를 리스트로 만들지 않고 흘려 보내는 파이프라인의 기본입니다.
    
    
    for gets an iterator from an iterable and calls next() repeatedly. A function containing yield becomes a generator, producing values one at a time on demand, pausing and resuming with its state kept. It is the basis of pipelines that stream big data instead of building lists.
    

    def squares(n):
    for i in range(n):
        yield i * i

g = squares(5)
print(next(g), next(g), list(g))   # 나머지를 한꺼번에 소비

import sys

    def read_lines():
    yield from ["10", "x", "30", ""]

    ⑤ 함수는 값이다: 클로저와 데코레이터⑤ Functions are values: closures and decorators
    
    
    함수를 변수에 담고, 인자로 넘기고, 함수 안에서 만들어 돌려줄 수 있습니다. 안쪽 함수가 바깥 변수를 기억하면 클로저이고, 이를 이용해 함수를 감싸는 것이 데코레이터(@)입니다. 로깅 · 캐시 · 권한 확인 같은 횡단 관심사를 본문 코드와 분리합니다. functools.wraps를 빠뜨리면 원래 함수의 이름 · 문서가 사라집니다.
    
    
    Functions can be stored in variables, passed as arguments, and created and returned inside functions. When an inner function remembers an outer variable it is a closure, and wrapping a function with one is a decorator (@). It separates cross-cutting concerns like logging, caching and permission checks from the main code. Forget functools.wraps and the original name and docstring vanish.
    

    import functools

def logged(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print("call", fn.__name__, args)
        return fn(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    """두 수의 합"""
    return a + b

print(add(2, 3), add.__name__, add.__doc__)
    call add (2, 3)

    __repr__ · __eq__ · __len__ · __iter__ 같은 던더(dunder) 메서드를 정의하면 내 클래스가 내장 타입처럼 print · == · len() · for에 반응합니다. 값을 담는 클래스는 @dataclass가 __init__ · __repr__ · __eq__를 만들어 주고, frozen=True면 불변 + 해시 가능해져 딕셔너리 키로 쓸 수 있습니다.
    
    
    Defining dunder methods such as __repr__, __eq__, __len__ and __iter__ makes your class respond to print, ==, len() and for like a built-in. For value classes @dataclass writes __init__, __repr__ and __eq__ for you, and frozen=True makes it immutable and hashable, usable as a dict key.

    ⑦ 예외와 컨텍스트 매니저⑦ Exceptions and context managers
    
    
    try / except / else / finally에서 else는 "예외가 없을 때", finally는 "무슨 일이 있어도" 실행됩니다. with는 자원의 열기 · 닫기를 짝지어 예외가 나도 반드시 정리합니다(파일 · 잠금 · DB 연결). @contextmanager로 직접 만들 수 있습니다. 파이썬은 "허락보다 용서(EAFP)": 먼저 검사하기보다 시도하고 예외를 처리하는 방식을 선호합니다.
    
    
    In try / except / else / finally, else runs "when there was no exception" and finally "no matter what". with pairs opening and closing a resource so it is always cleaned up even on exceptions (files, locks, DB connections), and you can write your own with @contextmanager. Python favours "easier to ask forgiveness than permission" (EAFP): try, then handle the exception, rather than check first.
    

    from contextlib import contextmanager

@contextmanager
def opened(name):
    print("open", name)
    try:
        yield name
    finally:
        print("close", name)       # 예외가 나도 실행됨

try:
    with opened("a.txt") as f:
        print("work", f)
        raise ValueError("boom")
except ValueError as e:
    print("caught", e)
else:
    print("no error")
finally:
    print("done")
    open a.txt
work a.txt
close a.txt
caught boom
done

    ⑨ 동시성: GIL, 스레드, 프로세스, asyncio⑨ Concurrency: the GIL, threads, processes and asyncio
    
    
    GIL 때문에 CPython 의 스레드는 CPU 계산을 병렬로 못 합니다. 그러나 I/O 대기(네트워크 · 파일) 동안에는 다른 스레드가 돌아 스레드가 유효합니다. CPU 병렬은 multiprocessing/ProcessPoolExecutor, 수천 개의 대기 작업은 asyncio(한 스레드에서 await 지점마다 양보)가 맞습니다. 동시 접속 처리 페이지의 이벤트 루프와 같은 원리입니다.
    
    
    Because of the GIL, CPython threads cannot run CPU work in parallel. During I/O waits (network, files), though, other threads run, so threads help. For CPU parallelism use multiprocessing/ProcessPoolExecutor; for thousands of waiting tasks, asyncio (one thread yielding at each await). Same principle as the event loop on the Handling many connections page.
    

    import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)          # 기다리는 동안 다른 작업이 진행
    return f"{name}:{delay}"

async def main():
    results = await asyncio.gather(fetch("a", 0.2), fetch("b", 0.1), fetch("c", 0.15))
    print(results)                      # 끝나는 순서가 아니라 넘긴 순서대로

asyncio.run(main())                     # 전체 0.2초 (순차라면 0.45초)
    ['a:0.2', 'b:0.1', 'c:0.15']

    순수 파이썬 반복문은 느리므로 ① 자료구조를 맞게(in 검사는 list 가 O(n), set · dict 는 평균 O(1)) ② 내장 함수 · 표준 라이브러리(C 로 구현)를 쓰고 ③ 수치 계산은 NumPy 같은 벡터화에 맡깁니다. 병목은 짐작이 아니라 cProfile로 재고, 시간 비교는 timeit으로 합니다.

Measure bottlenecks with cProfile, not guesses, and compare timings with timeit.

    흔한 함정 7가지: 증상 → 원인 → 해결Seven common pitfalls: symptom → cause → fix
    
  
    ⚠ 가변 기본 인자⚠ A mutable default argument
    
    
    증상. 함수를 부를 때마다 리스트가 이전 호출의 값을 기억합니다.
    Symptom. The list remembers values from previous calls.
    
    
    def add_item(x, items=[]):
    items.append(x)
    return items

print(add_item(1))
print(add_item(2))               # [2] 를 기대했는데…
    [1]
[1, 2]
    

    
    원인. 기본값은 함수를 정의할 때 딱 한 번 만들어집니다. 가변 객체면 모든 호출이 그것을 공유합니다.
    Cause. The default is created once, when the function is defined. If mutable, every call shares it.
    
    
    해결. 기본값은 None으로 두고 함수 안에서 새로 만듭니다.
    Fix. Use None as the default and create the object inside the function.
    
    
    def add_item(x, items=None):
    if items is None:
        items = []
    items.append(x)
    return items

print(add_item(1))
print(add_item(2))
    [1]
[2]
    

  
    
  
    ⚠ [[0]*3]*3 — 같은 행이 세 번⚠ [[0]*3]*3: the same row three times
    
    
    증상. 한 칸을 고쳤는데 모든 행이 바뀝니다.
    Symptom. You change one cell and every row changes.
    
    
    m = [[0] * 3] * 3
m[0][0] = 1
print(m)
    [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
    

    
    원인. *는 안쪽 리스트를 복사하지 않고 같은 객체에 대한 참조를 3개 만듭니다.
    Cause. * does not copy the inner list; it makes three references to the same object.
    
    
    해결. 컴프리헨션으로 행마다 새 리스트를 만듭니다.
    Fix. Build a new list per row with a comprehension.
    
    
    m = [[0] * 3 for _ in range(3)]    # 행마다 새 리스트
m[0][0] = 1
print(m)
    [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
    

  
    
  
    ⚠ 클로저의 늦은 바인딩⚠ Late binding in closures
    
    
    증상. 람다 3개를 만들었는데 모두 같은 값을 돌려줍니다.
    Symptom. Three lambdas all return the same value.
    
    
    fs = [lambda: i for i in range(3)]
print([f() for f in fs])
    [2, 2, 2]
    

    
    원인. 클로저는 변수 값이 아니라 변수 자체를 기억하고, 호출 시점에 읽습니다. 그때 i는 마지막 값입니다.
    Cause. A closure remembers the variable, not its value, and reads it at call time, when i holds the last value.
    
    
    해결. 기본 인자(i=i)나 functools.partial로 값을 고정합니다.
    Fix. Freeze the value with a default argument (i=i) or functools.partial.
    
    
    fs = [lambda i=i: i for i in range(3)]   # 기본 인자로 "지금 값"을 고정
print([f() for f in fs])
    [0, 1, 2]
    

  
    
  
    ⚠ 반복 중에 리스트를 수정⚠ Modifying a list while iterating over it
    
    
    증상. 짝수를 모두 지웠는데 일부가 남습니다.
    Symptom. You removed all evens but some remain.
    
    
    xs = [2, 4, 6, 1]
for x in xs:
    if x % 2 == 0:
        xs.remove(x)
print(xs)
    [4, 1]
    

    
    원인. 지우면 뒤 원소가 한 칸 당겨지는데 반복자는 위치를 그대로 증가시켜 한 원소를 건너뜁니다.
    Cause. Removing shifts later items one step left while the iterator keeps advancing, so one item is skipped.
    
    
    해결. 순회하는 컬렉션은 고치지 말고 걸러낸 새 컬렉션을 만듭니다.
    Fix. Do not change the collection you iterate; build a new filtered one.
    
    
    xs = [2, 4, 6, 1]
xs = [x for x in xs if x % 2 != 0]     # 새 리스트를 만든다
print(xs)
    [1]
    

  
    
  
    ⚠ is 와 == 를 혼동⚠ Confusing is with ==
    
    
    증상. 같은 숫자인데 is가 False 입니다.
    Symptom. The same number but is says False.
    
    
    a = 1000
b = int("1000")
print(a == b, a is b)
    True False
    

    
    원인. is는 객체의 동일성을 봅니다. CPython 은 작은 정수(-5~256)만 캐시하므로 큰 수는 별개의 객체일 수 있습니다.
    Cause. is tests object identity. CPython caches only small ints (-5 to 256), so bigger numbers can be separate objects.
    
    
    해결. 값 비교는 ==. is는 None처럼 싱글톤을 확인할 때만 씁니다.
    Fix. Use == for values; reserve is for singletons like None.
    
    
    x = None
print(x is None)       # is 는 None · True · False 와 비교할 때만
    True
    

  
    
  
    ⚠ 부동소수점 비교⚠ Comparing floats
    
    
    증상. 0.1 + 0.2 == 0.3이 False 입니다.
    Symptom. 0.1 + 0.2 == 0.3 is False.
    
    
    print(0.1 + 0.2 == 0.3)
print(0.1 + 0.2)
    False

    원인. 이진 부동소수점은 0.1 을 정확히 표현하지 못해 아주 작은 오차가 있습니다(모든 언어 공통).
    Cause. Binary floating point cannot represent 0.1 exactly, leaving a tiny error (true in every language).
    
    
    해결. math.isclose로 오차 허용 비교, 돈 계산은 decimal.Decimal이나 정수(원 단위)로.
    Fix. Compare with tolerance via math.isclose; for money use decimal.Decimal or integer units.
    
    
    import math
from decimal import Decimal
print(math.isclose(0.1 + 0.2, 0.3))
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))   # 돈은 Decimal
    True
True
    

  
    
  
    ⚠ 내장 이름 덮어쓰기⚠ Shadowing a builtin
    
    
    증상. 멀쩡하던 list(...) 호출이 갑자기 오류입니다.
    Symptom. A list(...) call that worked suddenly fails.
    
    
    list = [1, 2]
try:
    print(list("ab"))
except TypeError as e:
    print("TypeError:", e)
    TypeError: 'list' object is not callable
    

    
    원인. list = [1, 2]처럼 내장 이름과 같은 변수를 만들면 이후 그 이름은 내 변수를 가리킵니다 (id · type · input · sum도 흔한 사고).
    Cause. A variable named like a builtin, e.g. list = [1, 2], makes the name point at yours from then on (id, type, input and sum are common victims).
    
    
    해결. 이름을 바꿉니다(items · values). 린터(ruff)가 이런 덮어쓰기를 경고합니다.
    Fix. Rename it (items, values). A linter (ruff) warns about shadowing.

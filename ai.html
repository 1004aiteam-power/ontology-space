AI가 온톨로지로
전력망을 이해하는 모습Watching AI understand
the grid through an ontology

LLM은 말을 잘하지만 우리 데이터는 모릅니다.
온톨로지는 AI에게 "무엇이 무엇이고, 무엇과 이어지는가"를 알려 주는 지도입니다.

An LLM speaks well but does not know your data.
An ontology is the map that tells it what each thing is and how it connects.

소개 페이지에서 "온톨로지는 AI가 지식을 익히는 가장 좋은 바탕"이라고 썼습니다. 이 페이지는 그 말을 두 가지 시연으로 보여 줍니다. 자연어 질문에 그래프로 답하는 GraphRAG와, 고장 영향을 한 단계씩 따라가는 AI 에이전트입니다.

The intro page claims that an ontology is the best foundation for AI to acquire knowledge. This page shows it in two demos: GraphRAG, answering natural-language questions from the graph, and an AI agent that traces a failure's impact step by step.

⚠ 시연용 페이지입니다This is a demo

이 페이지는 실제 LLM을 부르지 않습니다. AI가 하는 부분(Cypher 작성 · 생각 · 도구 선택)은 미리 작성한 예시입니다. 대신 Cypher 실행과 결과, 답과 보고서에 들어가는 이름 · 숫자는 브라우저에서 실제 그래프에 매번 계산합니다. 데이터는 모두 가상입니다.

This page calls no real LLM. The AI's part (writing Cypher, thinking, choosing tools) is pre-written. But the Cypher runs, and every name and number in the answers and report, are computed live on the real graph in your browser. All data is virtual.

같은 질문, 세 가지 방법One question, three approaches

① LLM만LLM alone

학습한 일반 지식으로 답합니다. 우리 회사 설비 · 선로 · 계약은 모르므로 그럴듯하게 지어내거나 "확인이 필요하다"로 끝납니다.

Answers from general training. It does not know your assets, feeders or contracts, so it makes things up or ends with "you would need to check".

② 문서 검색 (RAG)Document search (RAG)

관련 문서 조각을 찾아 붙여 줍니다. 한 문서에 적힌 사실은 잘 찾지만, "선로 → 자원 → VPP"처럼 여러 단계를 이어야 하는 질문에는 약합니다.

Finds document chunks and pastes them in. Good for facts written in one place, weak on questions that must chain several hops such as feeder → resource → VPP.

③ 온톨로지 + 그래프 (GraphRAG)Ontology + graph (GraphRAG)

온톨로지가 정한 관계를 따라가는 질의를 만들고, 그 결과로만 답합니다. 답의 근거 경로를 보여 줄 수 있어 사람이 검증할 수 있습니다.

Writes a query that follows the relations the ontology defines, and answers only from the result. The evidence path can be shown, so people can check it.

질문→온톨로지 스키마→LLM이 Cypher 작성→그래프 DB 실행→결과로만 답→근거 경로
Question→Ontology schema→LLM writes Cypher→Run on graph DB→Answer from results→Evidence path

초록 테두리 = 온톨로지와 그래프가 하는 일. LLM은 질문을 질의로 바꾸고, 결과를 사람의 말로 옮기는 일만 합니다.

Green = the ontology and graph's job. The LLM only turns the question into a query and the result into plain words.

시연 1. GraphRAG: 질문에 그래프로 답하기Demo 1. GraphRAG: answering from the graph

VPP 가상 전력시장의 그래프(VPP 10개 · DER 81개 · 배전선로 15개 · 입찰 · 정산 · 출력제한 + 디지털 트윈 변전소)에 묻습니다. 질문을 고르고 한 단계씩 넘겨 보세요.

We ask the VPP virtual market graph (10 VPPs, 81 DER, 15 feeders, bids, settlements, curtailments + digital-twin substations). Pick a question and step through.

    시연 2. AI 에이전트: 고장 영향을 단계별로 추론Demo 2. AI agent: reasoning through a failure step by step

    에이전트는 질문 하나로 끝내지 않고 생각 → 도구 사용 → 관찰을 되풀이합니다. 여기서 도구는 모두 자산관리 · 배전선로 · 고장 영향 온톨로지 위의 질의입니다. 에이전트는 무엇을 물을지만 고르고, 답은 그래프가 냅니다.

    An agent does not stop at one query: it loops think → use a tool → observe. Every tool here is a query over the asset, feeder and failure impact ontologies. The agent only decides what to ask; the graph gives the answers.

      에이전트가 지금까지 찾은 것What the agent has found so far

      실제로 만든다면Building it for real

      1. 스키마를 프롬프트에1. Schema in the prompt

      온톨로지에서 라벨 · 관계 · 뜻을 뽑아(시연 1의 2단계) 시스템 프롬프트에 넣고, 잘 된 질의 예시 몇 개를 함께 줍니다. 온톨로지가 바뀌면 프롬프트도 자동으로 바뀝니다.

      Extract labels, relations and meanings from the ontology (step 2 of demo 1) into the system prompt, plus a few good example queries. Change the ontology and the prompt follows.

      2. 질의는 읽기 전용으로2. Read-only queries

      LLM이 쓴 Cypher는 읽기 전용 권한으로만 실행합니다. 오류가 나면 오류 메시지를 돌려줘 한두 번 고치게 하고, 결과가 비면 "모름"이라고 답하게 합니다.

      Run LLM-written Cypher with read-only rights. On an error, hand the message back for one or two fixes; on an empty result, answer "unknown".

      3. 에이전트 도구 = 검증된 질의3. Agent tools = vetted queries

      자주 쓰는 질문(하류 추적, 연계 개폐기, 진단 이력)은 사람이 검증한 질의를 도구로 만들어 둡니다. LLM은 도구를 고르고 인자만 채우므로 실수가 줄어듭니다.

      Turn frequent questions (downstream trace, tie switches, diagnoses) into human-vetted queries exposed as tools. The LLM only picks tools and fills arguments, so mistakes drop.

      4. 평가와 근거4. Evaluation and evidence

      정답 질의가 있는 질문 세트로 정답률을 재고, 답마다 근거 노드 · 경로를 함께 보여 사람이 확인하게 합니다. 전력 설비 판단은 최종적으로 사람이 내립니다.

      Measure accuracy on a question set with reference queries, and show evidence nodes and paths with every answer. Final decisions on grid assets stay with people.

      💡 이 시연이 보여 주는 것What this demo shows

      AI가 똑똑해서 맞는 답을 내는 것이 아닙니다. 온톨로지가 "무엇이 무엇과 이어지는가"를 정해 두었기 때문에 질문을 정확한 질의로 바꿀 수 있고, 답에 근거를 붙일 수 있습니다. 시연 1의 세 번째 질문처럼, 그래프에 없는 것(날씨)은 "모른다"고 말할 수 있다는 것도 중요합니다.

      The AI is not right because it is clever. It is right because the ontology fixed what connects to what, so a question can become a precise query and an answer can carry evidence. Equally important, as in demo 1's third question, it can say "unknown" for what the graph does not hold (the weather).

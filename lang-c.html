⚙️ C 언어: 메모리를 직접 쥔다는 것C: holding the memory yourself

C 는 운영체제와 데이터베이스, 다른 언어의 런타임까지 밑바닥을 이루는 언어입니다. 가장 빠르고 하드웨어에 가까운 대신 메모리를 직접 관리하고 모든 책임이 프로그래머에게 있습니다. 문법 입문은 건너뛰고 포인터 · 메모리 수명 · 정의되지 않은 동작처럼 중급의 문턱이 되는 개념을 컴파일해 본 코드로 설명합니다.

C forms the bottom layer of operating systems, databases and other languages' runtimes. It is the fastest and closest to the hardware, but you manage memory yourself and all responsibility rests on the programmer. Skipping syntax basics, this page explains the concepts that form the intermediate threshold — pointers, memory lifetime and undefined behaviour — with code that was actually compiled.

코드와 출력은 제작 환경(gcc 13, Linux 64비트)에서 실행한 결과입니다. 크기 · 오류 문구는 플랫폼과 컴파일러 버전에 따라 다를 수 있습니다. 시연은 개념 설명용 모형입니다.

Code and output come from running gcc 13 on 64-bit Linux in the authoring environment; sizes and error wording may differ by platform and compiler version. The demo is a conceptual model.

    ① 메모리는 세 곳: 스택 · 힙 · 정적① Memory lives in three places: stack, heap, static
    
    
    지역 변수는 함수 호출 때 스택에 잡히고 함수가 끝나면 사라집니다. malloc으로 얻는 힙 블록은 free할 때까지 남습니다. 전역 변수와 static 지역 변수는 정적 영역에 있어 프로그램 내내 살아 있습니다. 각각의 수명을 알면 "왜 이 값이 사라졌나 / 왜 안 지워지나"가 보입니다. (위 시연이 힙 블록의 수명을 한 줄씩 보여 줍니다.)
    
    
    A local variable is placed on the stack at the call and vanishes when the function ends. A heap block from malloc stays until you free it. Globals and static locals live in the static area for the whole run. Knowing each lifetime explains "why did this value disappear / why does it not go away". (The demo above shows a heap block's lifetime line by line.)
    

    #include <stdio.h>

int counter = 0;                       // 정적 영역: 프로그램 내내

void tick(void) {
    static int calls = 0;              // 정적: 함수가 끝나도 값이 남음
    int local = 10;                    // 스택: 호출마다 새로 만들어짐
    calls++;
    counter += local;
    printf("calls=%d counter=%d\n", calls, counter);
}

int main(void) {
    tick();
    tick();
    printf("%zu %zu %zu\n", sizeof(int), sizeof(long), sizeof(void *));
    return 0;
}

    The last line is for 64-bit Linux and macOS (64-bit Windows has a 4-byte long). Sizes differ by platform, so use sizeof and the fixed-width integers of <stdint.h>.
      
    
  
    ② 포인터와 배열: a[i] 는 *(a+i)② Pointers and arrays: a[i] is *(a+i)
    
    
    포인터는 주소를 담는 변수입니다. 배열 이름은 대부분의 식에서 첫 원소의 주소로 "붕괴"하고, 포인터에 1 을 더하면 원소 크기만큼 움직입니다(바이트가 아니라). 그래서 a[i]와 *(a + i)는 같은 뜻이고 1[a]도 됩니다. 함수 매개변수의 int arr[]는 사실 int *arr라서 길이 정보가 사라지니 길이를 따로 넘겨야 합니다.
    
    
    A pointer is a variable holding an address. In most expressions an array name "decays" to the address of its first element, and adding 1 to a pointer moves it by one element (not one byte). So a[i] and *(a + i) mean the same, and even 1[a] works. A function parameter int arr[] is really int *arr, so the length is lost and must be passed separately.
    

    #include <stdio.h>

void show(int arr[], size_t n) {
    printf("param sizeof=%zu n=%zu\n", sizeof(arr), n);   // 포인터의 크기일 뿐
}

int main(void) {
    int a[] = {10, 20, 30};
    int *p = a;                          // 붕괴: &a[0]
    printf("%d %d %d\n", a[1], *(p + 1), 1[a]);
    printf("%td\n", (p + 2) - p);        // 원소 개수의 차이
    printf("%zu %zu\n", sizeof(a), sizeof(p));   // 배열 전체 vs 포인터 하나
    show(a, sizeof a / sizeof a[0]);
    return 0;
}
    20 20 20
2
12 8
param sizeof=8 n=3
    
  
    
  
    ③ 동적 메모리와 "누가 free 하나"③ Dynamic memory and "who frees it"
    
    
    malloc(초기화 안 함) · calloc(0 으로 채움) · realloc(크기 변경) · free. 규칙은 셋입니다: ① 실패(NULL)를 검사한다 ② 모든 블록에 "해제할 주인"이 한 명이다 ③ 해제 뒤에는 포인터를 쓰지 않는다. sizeof *p 관용구는 타입이 바뀌어도 크기가 따라옵니다. realloc은 실패 시 원래 블록을 그대로 두므로 결과를 임시 변수에 받아 확인합니다.
    
    
    malloc (uninitialised), calloc (zero-filled), realloc (resize), free. Three rules: ① check for failure (NULL) ② every block has exactly one owner responsible for freeing it ③ never touch the pointer after freeing. The sizeof *p idiom keeps the size right when the type changes. realloc leaves the old block untouched on failure, so take its result in a temporary and check it.
    

    #include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t n = 3;
    int *v = malloc(n * sizeof *v);           // sizeof *v : 타입이 바뀌어도 안전
    if (v == NULL) return 1;
    for (size_t i = 0; i < n; i++) v[i] = (int)(i * i);

    int *bigger = realloc(v, 5 * sizeof *v);  // 실패하면 v 는 그대로 살아 있음
    if (bigger == NULL) { free(v); return 1; }
    v = bigger;
    v[3] = 9; v[4] = 16;

    for (size_t i = 0; i < 5; i++) printf("%d ", v[i]);
    printf("\n");
    free(v);
    v = NULL;                                  // 매달린 포인터를 남기지 않기
    return 0;
}
    0 1 4 9 16 
    
  
    
  
    ④ 문자열은 널로 끝나는 char 배열④ A string is a NUL-terminated char array
    
    
    C 에는 문자열 타입이 없습니다. "abc"는 {'a','b','c','\0'} 4바이트이고, 모든 문자열 함수는 끝의 \0을 찾아 길이를 압니다. 그래서 strlen은 3, sizeof는 4 입니다. 문자열 리터럴은 읽기 전용이므로 char *s = "abc"의 내용을 고치면 안 되고, 고치려면 char s[] = "abc"로 복사본을 만듭니다. 복사는 strcpy보다 크기를 받는 snprintf가 안전합니다.
    
    
    C has no string type. "abc" is four bytes {'a','b','c','\0'} and every string function finds the length by looking for the trailing \0. So strlen is 3 and sizeof is 4. String literals are read-only: do not modify char *s = "abc"; use char s[] = "abc" for a modifiable copy. For copying, snprintf, which takes a size, is safer than strcpy.
    

    #include <stdio.h>
#include <string.h>

int main(void) {
    char s[] = "abc";                       // 4바이트: a b c \0
    printf("%zu %zu\n", strlen(s), sizeof s);

    char a[] = "hi", b[] = "hi";
    printf("%d %d\n", a == b, strcmp(a, b) == 0);   // == 는 주소 비교!

    char buf[8];
    int n = snprintf(buf, sizeof buf, "%s-%s", "grid", "sub-A");
    printf("%s (%d chars wanted)\n", buf, n);       // 잘리지만 항상 \0 으로 끝남
    return 0;
}

    ⑤ 구조체 · 정렬 · 함수 포인터⑤ Structs, alignment and function pointers
    
    
    struct는 값을 묶고, 컴파일러는 접근 속도를 위해 필드 사이에 패딩을 넣습니다(필드 순서만 바꿔도 크기가 달라짐). 함수 포인터는 "동작을 인자로 넘기는" 방법으로 콜백 · 정렬 비교 · 간단한 다형성(구조체 안의 함수 포인터 표 = 객체지향의 시작)에 쓰입니다. 표준 라이브러리의 qsort가 대표 예입니다.
    
    
    A struct groups values, and for speed the compiler inserts padding between fields (reordering fields alone changes the size). A function pointer passes behaviour as an argument, used for callbacks, comparison in sorting and simple polymorphism (a table of function pointers in a struct is the seed of object orientation). The standard qsort is the classic example.
    

    #include <stdio.h>
#include <stdlib.h>

typedef struct { char tag; int health; char kind; } Loose;   // 패딩이 생김
typedef struct { int health; char tag; char kind; } Tight;   // 같은 필드, 다른 순서

typedef struct { const char *id; int health; } Asset;

static int by_health_desc(const void *a, const void *b) {
    const Asset *x = a, *y = b;
    return (y->health > x->health) - (y->health < x->health);
}

int main(void) {
    printf("%zu %zu\n", sizeof(Loose), sizeof(Tight));
    Asset v[] = {{"T1", 82}, {"T2", 64}, {"B1", 91}};
    qsort(v, 3, sizeof v[0], by_health_desc);           // 비교 함수를 넘김
    for (int i = 0; i < 3; i++) printf("%s:%d ", v[i].id, v[i].health);
    printf("\n");
    return 0;
}

B1:91 T1:82 T2:64 
    
  
    
  
    ⑥ 전처리기 · 헤더 · 링크⑥ The preprocessor, headers and linking
    
    
    #include와 #define은 컴파일 전에 글자를 바꾸는 단계(전처리)입니다. 헤더에는 선언(이런 함수가 있다)을, .c에는 정의(실제 몸체)를 두고, 헤더는 #ifndef 가드로 중복 포함을 막습니다. 링커가 여러 .c의 오브젝트를 이어 붙이며 "undefined reference"는 선언만 있고 정의가 없을 때 납니다. 매크로는 글자 치환이라 인자를 괄호로 감싸지 않으면 우선순위가 깨집니다.
    
    
    #include and #define are a step (preprocessing) that rewrites text before compilation. Put declarations (such a function exists) in headers and definitions (the real bodies) in .c files, guarding headers against double inclusion with #ifndef. The linker joins the object files of several .c files; "undefined reference" means a declaration without a definition. A macro is text substitution, so without parentheses around arguments precedence breaks.
    

    #include <stdio.h>

#define SQUARE_BAD(x) x * x             // 글자 그대로 바뀜
#define SQUARE(x) ((x) * (x))           // 인자와 전체를 괄호로

static inline int square(int x) { return x * x; }   // 가능하면 함수가 안전

int main(void) {
    printf("%d %d %d\n", SQUARE_BAD(1 + 2), SQUARE(1 + 2), square(1 + 2));
    return 0;
}
    5 9 9
    

    gcc -E main.c      # 전처리만 (매크로 · include 가 펼쳐진 결과)
gcc -S main.c      # 어셈블리까지
gcc -c main.c      # 오브젝트 파일 main.o (링크 전)
gcc main.o util.o -o app    # 링크 → 실행 파일
gcc -Wall -Wextra -std=c17 -g main.c -o app   # 평소 권장 옵션
    
  
    
  
    ⑦ 정의되지 않은 동작(UB): 무엇이든 일어날 수 있다⑦ Undefined behaviour: anything can happen
    
    
    배열 범위 밖 접근, 해제한 메모리 사용, 초기화하지 않은 변수 읽기, 부호 있는 정수 오버플로, NULL 역참조 같은 코드는 표준이 "아무 보장 없음"이라 합니다. 컴파일러는 UB 가 없다고 가정하고 최적화하므로 디버그 빌드에서는 멀쩡하다 최적화하면 터지는 일이 흔합니다. 반대로 부호 없는 정수의 오버플로는 정의되어 있어 2 의 거듭제곱으로 돌아갑니다. UB 는 눈으로 찾기 어려우니 도구(경고 · Sanitizer · valgrind)로 잡습니다.
    
    
    Out-of-bounds access, using freed memory, reading an uninitialised variable, signed integer overflow and dereferencing NULL are cases where the standard promises "nothing". The compiler optimises assuming UB never happens, so code that works in a debug build often breaks when optimised. By contrast unsigned overflow is defined and wraps modulo a power of two. UB is hard to spot by eye, so catch it with tools (warnings, sanitizers, valgrind).
    

    #include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t u = 255;
    u++;                                  // 부호 없는 오버플로: 정의됨 → 0
    printf("%u\n", u);
    // int big = 2147483647; big++;       // 부호 있는 오버플로: UB (결과를 믿을 수 없음)
    return 0;
}

    gcc -g -fsanitize=address,undefined -Wall -Wextra main.c -o app
./app          # 범위 밖 · 해제 후 사용 · 오버플로 등을 실행 중에 정확한 줄과 함께 보고
# mac(clang)에서도 같은 옵션이 동작합니다. valgrind 는 최신 mac 에서 지원이 제한적이라 Sanitizer 를 권합니다.
    
  
    
  
    ⑧ 비트 연산과 고정 폭 정수⑧ Bit operations and fixed-width integers
    
    
    플래그 · 하드웨어 레지스터 · 프로토콜 필드는 비트 단위로 다룹니다: |(켜기) · &(검사 · 끄기, ~와 함께) · ^(뒤집기) · << >>. 크기가 중요하면 <stdint.h>의 uint8_t · int32_t 처럼 폭이 고정된 타입을 쓰고, 시프트와 마스크는 부호 없는 타입에서 하세요(부호 있는 값의 시프트는 UB 가 되기 쉽습니다).
    
    
    Flags, hardware registers and protocol fields are handled bit by bit: | (set), & (test, or clear with ~), ^ (toggle), << >>. When size matters use the fixed-width types of <stdint.h> such as uint8_t and int32_t, and shift and mask on unsigned types (shifting signed values easily becomes UB).
    

    #include <stdio.h>
#include <stdint.h>

enum { READ = 1u << 0, WRITE = 1u << 1, EXEC = 1u << 2 };

int main(void) {
    uint8_t perm = 0;
    perm |= READ | WRITE;                 // 켜기
    perm &= (uint8_t)~WRITE;              // 끄기
    perm ^= EXEC;                         // 뒤집기
    printf("read=%d write=%d exec=%d value=%u\n",
           (perm & READ) != 0, (perm & WRITE) != 0, (perm & EXEC) != 0, perm);
    return 0;
}
    read=1 write=0 exec=1 value=5
    
  
    
  
    ⑨ 오류 처리 관례: 반환 코드 · errno · goto cleanup⑨ Error handling idioms: return codes, errno, goto cleanup
    
    
    C 에는 예외가 없어 함수가 성공/실패를 반환값(0 · -1 · NULL)으로 알리고, 이유는 errno에 둡니다. 자원을 여러 개 잡는 함수에서는 실패 지점마다 정리 코드를 반복하는 대신 goto cleanup 한 곳으로 모아 해제 누락을 막는 것이 커널 · 라이브러리의 관용입니다. 반환값을 무시하지 마세요(fopen · malloc · fclose).
    
    
    C has no exceptions, so functions signal success or failure through the return value (0, -1, NULL) and put the reason in errno. In functions acquiring several resources, instead of repeating cleanup at each failure point, funnelling to a single goto cleanup prevents missed releases, a kernel and library idiom. Never ignore return values (fopen, malloc, fclose).
    

    #include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

static int load(const char *path) {
    int rc = -1;
    FILE *f = NULL;
    char *buf = NULL;

    f = fopen(path, "r");
    if (!f) { printf("fopen: %s\n", strerror(errno)); goto cleanup; }
    buf = malloc(64);
    if (!buf) goto cleanup;
    rc = 0;

cleanup:                                  // 어느 지점에서 실패해도 여기서 한 번에 정리
    free(buf);
    if (f) fclose(f);
    return rc;
}

int main(void) {
    printf("rc=%d\n", load("/no/such/file"));
    return 0;
}
    fopen: No such file or directory
rc=-1
    
  
    

    


    
  
    흔한 함정 5가지: 증상 → 원인 → 해결Five common pitfalls: symptom → cause → fix
    
  
    ⚠ strncpy 는 널 문자를 안 붙인다⚠ strncpy does not add a NUL
    
    
    증상. 복사한 문자열을 출력했더니 뒤에 쓰레기가 붙습니다.
    Symptom. The copied string prints with garbage after it.
    
    
    #include <stdio.h>
#include <string.h>

int main(void) {
    char buf[8] = {'X', 'X', 'X', 'X', 'X', 'X', 'X', 0};   // 뒤가 X 라 문제가 눈에 보임
    strncpy(buf, "abcdefgh", 4);          // 4바이트만 복사, \0 없음
    printf("%s\n", buf);
    return 0;
}
    abcdXXX
    

    
    원인. strncpy는 원본이 n보다 길면 널 종료 없이 정확히 n바이트만 복사합니다.
    Cause. strncpy copies exactly n bytes without a terminator when the source is longer.
    
    
    해결. 크기를 받아 항상 널로 끝내 주는 snprintf를 씁니다.
    Fix. Use snprintf, which takes a size and always terminates.
    
    
    #include <stdio.h>

int main(void) {
    char buf[8];
    snprintf(buf, sizeof buf, "%.4s", "abcdefgh");   // 항상 \0 으로 끝남
    printf("%s\n", buf);
    return 0;
}
    abcd
    

  
    
  
    ⚠ 문자열을 == 로 비교⚠ Comparing strings with ==
    
    
    증상. 내용이 같은데 "다르다"고 나옵니다.
    Symptom. Equal contents report "different".
    
    
    #include <stdio.h>
#include <string.h>

int main(void) {
    char a[] = "grid", b[] = "grid";
    printf("%d\n", a == b);
    printf("%d\n", strcmp(a, b) == 0);
    return 0;
}
    0
1
    

    
    원인. ==는 주소를 비교합니다. 서로 다른 배열은 내용이 같아도 주소가 다릅니다.
    Cause. == compares addresses; separate arrays differ in address even with equal contents.
    
    
    해결. 내용 비교는 strcmp(같으면 0), 크기 제한이 필요하면 strncmp.
    Fix. Compare contents with strcmp (0 when equal), or strncmp to limit length.
    
    
  
    
  
    ⚠ 정수 나눗셈⚠ Integer division
    
    
    증상. 7 / 2가 3.5 가 아니라 3 입니다.
    Symptom. 7 / 2 gives 3, not 3.5.
    
    
    #include <stdio.h>

int main(void) {
    int a = 7, b = 2;
    double wrong = a / b;                 // 먼저 3 으로 잘리고 3.0 이 됨
    double right = (double)a / b;         // 한쪽을 먼저 double 로
    printf("%.1f %.1f\n", wrong, right);
    return 0;
}
    3.0 3.5
    

    
    원인. 두 피연산자가 정수면 정수 나눗셈(소수 버림)입니다. 결과를 나중에 double 에 담아도 이미 잘려 있습니다.
    Cause. With two integer operands it is integer division (fraction dropped); storing the result in a double afterwards is too late.
    
    
    해결. 피연산자 하나를 먼저 double로 변환합니다.
    Fix. Convert one operand to double first.
    
    
  
    
  
    ⚠ 지역 변수의 주소를 돌려줌 / 초기화 안 한 변수⚠ Returning a local's address / uninitialised variables
    
    
    증상. 값이 가끔 맞고 가끔 쓰레기이며, 최적화 수준에 따라 달라집니다.
    Symptom. The value is sometimes right, sometimes garbage, and changes with the optimisation level.
    
    
    int *bad(void) {
    int x = 5;
    return &x;          // 반환 즉시 x 는 사라진다 → 정의되지 않은 동작
}

int main(void) {
    int n;              // 초기화 안 함
    return n;           // 읽는 순간 정의되지 않은 동작
}
    

    
    원인. 함수가 끝나면 스택의 지역 변수는 사라지는데 그 주소를 가진 포인터가 남습니다(매달린 포인터). 초기화 안 한 지역 변수에는 이전에 스택에 있던 값이 들어 있습니다.
    Cause. When a function ends its stack locals vanish but a pointer to them remains (dangling pointer). An uninitialised local contains whatever the stack held before.
    
    
    해결. -Wall -Wextra가 둘 다 경고합니다(-Wreturn-local-addr · -Wuninitialized). 경고를 무시하지 말고 -Werror로 오류화하세요. 값은 호출자가 넘긴 버퍼에 쓰거나 malloc으로 돌려줍니다.
    Fix. -Wall -Wextra warns about both (-Wreturn-local-addr, -Wuninitialized). Do not ignore warnings; make them errors with -Werror. Write results into a caller-supplied buffer or return a malloced block.
    
    
  
    
  
    ⚠ off-by-one: 경계 하나 차이⚠ Off-by-one errors
    
    
    증상. 마지막 원소를 빠뜨리거나, 한 칸 넘어 씁니다 (i <= n).
    Symptom. The last element is missed, or one cell too many is written (i <= n).
    
    
    int a[4];
for (int i = 0; i <= 4; i++)   // i == 4 일 때 범위 밖 쓰기
    a[i] = i;
    

    
    원인. 길이 n 인 배열의 유효 인덱스는 0 ~ n-1 입니다. 닫힌 구간으로 쓰는 습관이 가장 흔한 원인입니다.
    Cause. An array of length n has valid indexes 0 to n-1. A habit of closed ranges is the commonest cause.
    
    
    해결. i < n으로 쓰고, 길이는 sizeof a / sizeof a[0]로 구합니다. 위의 Sanitizer 가 이런 오류를 실행 중에 잡아 줍니다.
    Fix. Write i < n and get the length from sizeof a / sizeof a[0]. The sanitizer above catches this at run time.

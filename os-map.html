운영체제 · 개요OPERATING SYSTEMS · OVERVIEW

🖥️ 운영체제는
프로그램과 하드웨어 사이의 심판The operating system:
referee between programs and hardware

프로그램은 디스크에 직접 쓰지도, 다른 프로그램의 메모리를 보지도, CPU를 혼자 차지하지도 못합니다. 그런 일은 모두 커널에게 부탁해야 하고, 그 부탁이 시스템 호출입니다. CPU에는 사용자 모드와 커널 모드가 있어서, 그 경계를 넘는 길은 정해진 몇 개의 문(시스템 호출, 인터럽트, 예외)뿐입니다. 그 문을 지나가는 과정을 한 단계씩 따라갑니다.

A program cannot write to the disk directly, look at another program's memory, or keep the CPU to itself. All of that must be requested from the kernel, and such a request is a system call. The CPU has a user mode and a kernel mode, and the only ways across are a few fixed gates: system calls, interrupts and exceptions. Follow the trip through those gates step by step.

리눅스 x86-64를 기준으로 크게 줄여 적었습니다. 시스템 호출 번호(read 0 · write 1 · getpid 39)는 커널의 표와 같고, 사용자 모드와 커널 모드가 정해진 문에서만 바뀌는지를 tests/os.test.mjs가 확인합니다.

Greatly simplified, based on Linux x86-64. The syscall numbers (read 0 · write 1 · getpid 39) match the kernel's table, and tests/os.test.mjs checks that user and kernel mode change only at the defined gates.

    알아 둘 원리Principles worth knowing

    ① 두 가지 모드① Two modes

    CPU는 지금 어느 모드인지 비트로 기억합니다. 사용자 모드에서는 장치 입출력, 인터럽트 끄기, 페이지 테이블 바꾸기 같은 특권 명령이 거부됩니다. 커널 모드로 가는 길은 커널이 부팅 때 정해 둔 진입점뿐이라, 프로그램이 커널 코드의 아무 곳으로나 뛰어들 수 없습니다. 이 하드웨어 경계가 모든 보호의 바탕입니다.

    The CPU remembers its current mode in a bit. In user mode, privileged instructions such as device I/O, disabling interrupts or switching page tables are refused. The only way into kernel mode is through entry points the kernel registered at boot, so a program cannot jump into arbitrary kernel code. This hardware boundary underlies all protection.

    ② 시스템 호출 · 인터럽트 · 예외② System calls, interrupts and exceptions

    커널에 들어가는 문은 셋입니다. 시스템 호출은 프로그램이 스스로 부탁하는 것(write, read). 인터럽트는 장치가 바깥에서 알리는 것(키보드, SSD 완료, 타이머). 예외는 CPU가 명령을 실행하다 문제를 만난 것(페이지 폴트, 0으로 나누기, 특권 명령). 앞의 실험이 각각을 하나씩 보여 줍니다.

    There are three gates into the kernel. A system call is a request the program makes itself (write, read). An interrupt is a device signalling from outside (keyboard, SSD completion, timer). An exception is the CPU hitting a problem while executing (page fault, divide by zero, privileged instruction). The scenarios above show each of them.

    ③ "모든 것은 파일"③ "Everything is a file"

    유닉스 계열은 일반 파일, 터미널, 소켓, 파이프, 장치를 모두 파일 번호(fd) 하나로 다루고 같은 read · write로 읽고 씁니다. 앞의 시나리오에서 파일 쓰기와 키보드 읽기가 같은 호출을 쓴 것이 그 예입니다. 아래 계층이 무엇이든 위에서는 같은 모양으로 보이게 하는 추상화가 운영체제의 핵심 일입니다.

    Unix-like systems handle regular files, terminals, sockets, pipes and devices all through a file descriptor, read and written with the same read and write. Writing a file and reading the keyboard used the same calls above. Making everything look the same from above whatever lies below, abstraction, is a core job of an OS.

    ④ 커널을 오가는 데도 비용이 든다④ Kernel crossings are not free

    모드를 한 번 오갈 때마다 레지스터 저장 · 복원과 보안 대책(Meltdown 이후의 페이지 테이블 분리 등)으로 수십~수백 ns가 듭니다. 그래서 작은 쓰기를 모아 한 번에 보내고(버퍼링), 호출 여러 개를 한 번에 넘기는 인터페이스(리눅스 io_uring)가 생겼습니다. 동시 접속 처리의 epoll도 "준비된 것만 한 번에 묻기"로 호출 수를 줄이는 방법입니다.

    Each round trip costs tens to hundreds of ns for saving and restoring registers and for security measures (such as page-table isolation after Meltdown). Hence small writes are batched (buffering), and interfaces that submit many calls at once exist (Linux io_uring). epoll on the many-connections page likewise cuts calls by asking only for what is ready.

    ⑤ 임베디드와 실시간 OS⑤ Embedded and real-time OSes

    보호계전기, 인버터 제어기, 로봇 관절은 "평균적으로 빠름"이 아니라 "마감 시간을 절대 넘기지 않음"이 중요합니다. 그래서 FreeRTOS · Zephyr · VxWorks 같은 실시간 OS나 PREEMPT_RT를 켠 리눅스를 씁니다. 작은 마이크로컨트롤러는 메모리 보호(MMU)가 없어 사용자 · 커널 구분 없이 하나의 프로그램으로 돌기도 합니다.

    Protection relays, inverter controllers and robot joints care about never missing a deadline, not about being fast on average. They run real-time OSes such as FreeRTOS, Zephyr or VxWorks, or Linux with PREEMPT_RT. Small microcontrollers may lack memory protection (an MMU) altogether and run as a single program with no user/kernel split.

    ⑥ 이 모형이 생략한 것⑥ What this model leaves out

    인터럽트의 위 · 아래 절반 나누기(softirq), 여러 코어에서의 동시 진입, 시스템 호출 필터(seccomp), 가상화(하이퍼바이저의 또 다른 모드), 실제 레지스터 값과 시간은 넣지 않았습니다.

    Not included: splitting interrupt handling into top and bottom halves (softirq), simultaneous entry on several cores, syscall filtering (seccomp), virtualisation (the hypervisor's extra mode), and real register values and timings.
